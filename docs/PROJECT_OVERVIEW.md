# Project Overview

## 1. 프로젝트 목적

대학교 셔틀 이용자가 셔틀 위치를 확인하는 것에서 끝나지 않고, 셔틀에서 내린 뒤 목적 단과대학과 강의실까지 연속적으로 안내받을 수 있는 시스템을 구현한다.

실외와 실내에서 사용하는 위치 추정 방식은 다르지만 사용자는 하나의 서비스 흐름으로 이용할 수 있어야 한다.

```text
셔틀 위치 확인
→ 정류장 하차
→ 목적 단과대학까지 실외 보행 안내
→ 건물 진입 및 실내 측위 전환
→ 층·복도 이동 안내
→ 목적 강의실 도착
```

## 2. 문제 정의

일반적인 위치 안내 서비스는 실외 GPS 또는 차량 위치 확인에 집중되어 있다. 그러나 대학교 신입생, 방문자와 건물 구조에 익숙하지 않은 사용자는 셔틀에서 내린 뒤에도 다음 문제를 겪을 수 있다.

- 어느 정류장에서 내려야 하는지 판단하기 어렵다.
- 정류장에서 목적 단과대학까지의 이동 방향을 알기 어렵다.
- 건물 입구에 도착해도 내부 현재 위치를 파악하기 어렵다.
- 층, 복도, 계단과 엘리베이터 중 어느 방향으로 이동해야 하는지 알기 어렵다.
- 강의실 번호를 알아도 실제 위치와 입구를 찾기 어렵다.
- 실외 GPS 안내가 끝나는 지점과 실내 안내가 시작되는 지점이 연결되지 않는다.

본 프로젝트는 셔틀 위치 추적, 실외 보행 안내와 실내 강의실 안내 사이의 단절을 줄이는 것을 핵심 문제로 정의한다.

## 3. 대상 사용자와 이용 상황

### 주요 사용자

- 캠퍼스와 건물 구조가 익숙하지 않은 신입생
- 처음 방문하는 외부인과 행사 참가자
- 다른 단과대학 강의실을 찾아가는 재학생
- 이동 경로를 미리 확인하려는 셔틀 이용자

### 대표 이용 흐름

1. 사용자가 목적 강의실을 선택한다.
2. 서비스가 목적 건물과 이용할 셔틀 정보를 제시한다.
3. 버스에 장착된 T-Beam 위치를 이용해 셔틀 위치를 확인한다.
4. 하차 후 사용자의 휴대폰 GPS로 목적 단과대학 입구까지 안내한다.
5. 건물 진입을 확인한 뒤 실내 위치 추정 방식으로 전환한다.
6. 지도와 현재 위치를 연결해 목적 층과 강의실까지 안내한다.

## 4. 시스템 구성

### 4.1 셔틀 위치 추적

버스 내부에 장착한 T-Beam의 GPS 기능으로 셔틀 위치를 측정한다.

주요 과제는 다음과 같다.

- T-Beam GPS 데이터 수신과 전송
- 실제 운행 구간의 원시 위치 데이터 수집
- 위성 수, 신호 품질, 정지·이동 상태별 오차 분석
- GPS 보정 방식 선정과 구현
- 보정 전후 정확도와 지연 비교

현재 Arduino UNO 기반 원시 GPS 수집 스케치를 보존했으며, T-Beam 환경 확정과 실제 데이터 수집은 아직 진행 전이다.

### 4.2 정류장에서 건물까지의 실외 보행 안내

사용자가 셔틀에서 내린 뒤에는 버스의 T-Beam 좌표가 아니라 사용자의 휴대폰 GPS를 이용한다.

이 구간에서는 다음 기능이 필요하다.

- 사용자 휴대폰의 현재 위치 확인
- 정류장과 목적 단과대학 입구를 연결하는 보행 경로
- 건물 입구 접근 또는 진입 판단
- 실외 GPS 안내에서 실내 위치 추정으로 전환

이 전환 구간은 셔틀 안내와 강의실 안내를 하나의 서비스로 연결하는 핵심 과정이다.

### 4.3 건물 내부 위치 추정

건물 내부에서는 GPS 정확도가 낮기 때문에 휴대폰 센서를 이용한 PDR을 기본 방식으로 검토한다.

```text
PDR + 자기장 기반 보정 + 지도 정합
```

- 가속도계·자이로스코프를 이용한 걸음과 이동 방향 추정
- 자기장 정보를 이용한 위치 특징 확인과 PDR 누적 오차 보정
- 기압계를 이용한 층 변화 보조 판단
- 복도와 벽 구조를 이용한 지도 정합
- 계단·엘리베이터 이동과 층간 전환 판정

Wi-Fi RTT는 실내 위치 보조 후보로 검토한다. 다만 실제 건물의 무선 공유기와 사용자 휴대폰이 해당 기능을 지원하는지 확인하기 전이므로 현재 기본 방식으로 확정하지 않는다.

현재 3·4층 PDR 실험 화면과 4층 자기장 측정 자료가 준비되어 있으며, 실제 휴대폰 보행 실험과 보정 알고리즘 검증은 남아 있다.

### 4.4 건물 지도

IT융합대학 1~10층의 2D·3D 웹 지도 프로토타입을 구현했다.

- 1~10층 지도 데이터와 층별 2D 검토도
- 1~10층 단독 3D와 통합 3D
- 강의실 검색과 층 선택
- PDR·자기장 실험 화면
- 3·4층 GLB·LiDAR 참고 자료

2D 지도를 구조와 위치 데이터의 기준으로 사용하고, 3D 지도는 확정된 2D 구조를 시각화한다. 일부 층은 피난안내도 비례를 사용한 프로토타입이므로 현장 구조와 추가 자료를 이용한 최종 검수가 필요하다.

### 4.5 사용자 서비스와 앱

사용자가 목적지를 선택하면 셔틀 위치부터 강의실 도착까지 단계별 안내를 제공하는 것을 목표로 한다.

검토 중인 서비스 형태는 다음과 같다.

- 강의실 찾기: 현재 위치에서 지정 강의실까지 안내
- 신입생 안내: 셔틀, 건물과 주요 시설을 포함한 단계별 안내
- 2D 지도 안내: 현재 위치, 경로, 방향과 남은 거리 표시
- AR 안내: 카메라 화면에 다음 이동 방향과 화살표 표시

모바일 앱은 Windows 개발 환경과 센서·AR 기능 접근 조건을 고려해 Android를 우선 개발한다. Android에서 지도·센서·AR 기능을 검증한 뒤 iOS의 개발·배포 조건과 지원 범위를 검토한다.

## 5. 현재 프로젝트 범위

### 포함

- IT융합대학 1~10층 2D·3D 지도 제작과 검수
- 강의실 검색, 층 선택과 경로 데이터 준비
- 셔틀용 GPS 원시 데이터 수집과 보정 실험
- 휴대폰 GPS 기반 정류장·건물 연결 방식 설계
- PDR, 자기장, 기압계와 지도 정합 실험
- Android 우선 모바일 안내 앱과 AR 기능 설계

### 현재 단계에서 제외

- 검증되지 않은 센서 값을 실제 서비스 위치로 확정하는 것
- 피난안내도만으로 실제 건축 치수를 확정하는 것
- 모든 캠퍼스 건물과 노선을 한 번에 구현하는 것
- 현재 단계에서 iOS 앱 배포를 완료하는 것
- 충분한 실험 없이 Wi-Fi RTT 사용을 확정하는 것

## 6. 프로젝트 차별점

이 프로젝트의 핵심 차별점은 셔틀의 위치만 보여주는 BIS나 건물 내부 지도만 제공하는 서비스에서 끝나지 않는다는 점이다.

```text
실외 셔틀 위치 안내
→ 휴대폰 GPS 기반 하차 후 보행 안내
→ 실외·실내 위치 추정 전환
→ PDR·자기장·지도 정합 기반 실내 안내
→ 목적 강의실 도착
```

서로 다른 위치 추정 기술을 하나의 사용자 이동 과정으로 연결하고, 실제 제작한 건물 지도 위에서 검증하는 것이 본 프로젝트의 중심이다.

## 7. 성공 판단 기준

- 셔틀 위치 데이터가 실제 운행 환경에서 안정적으로 수집된다.
- 정류장에서 목적 건물 입구까지 휴대폰 GPS 안내가 이어진다.
- 건물 진입 후 실내 위치 추정으로 전환할 수 있다.
- PDR의 누적 오차와 자기장 간섭 조건을 정량적으로 기록할 수 있다.
- 현재 위치와 목적 강의실이 2D·3D 지도 좌표에 일관되게 연결된다.
- Android 실제 기기에서 목적지 선택부터 경로 안내까지 핵심 흐름을 재현할 수 있다.
- 검증하지 못한 위치와 센서 결과를 성공한 기능처럼 표시하지 않는다.
