# 실내측위 제품화 목표와 검증 게이트

작성일: 2026-09-19

이 문서는 `데모는 됐지만 학생이 실제로 쓰지 못하는 앱`으로 끝나는 상황을 피하기 위해, 연구 실험과 제품 채택을 분리한다. 좌표 평균 오차 하나보다 **시작 위치, 층, 올바른 복도 선택, 안정적인 안내, 도착 판정**을 우선한다.

## 1. 현재 구현과 실제 공백

|항목|현재 상태|제품화 판단|
|---|---|---|
|단순 메인복도 진행|진행방향을 유지하는 1차원 모드와 3걸음 연속 반전 확인이 구현됨|4·6~10층 기본 구조에는 사용 가능성이 있으나 다사용자 현장 검증 전|
|2·3층 분기|등록 포털 근처에서 일부 파티클을 분기시키는 코드가 있음|휴대폰 순간 헤딩으로 분기 후보가 생기며 `분기 후보→확정` 상태와 확정 히스테리시스가 없음|
|BLE 보정|PDR ±12m 게이트, 후보 우세 `0.55`, 격차 `0.12`, 최대 15% 약한 제안|정지 세션은 구분되지만 보행 중 복도 중간 오판이 있어 강제 위치 확정 금지|
|자기장 8걸음 V2|PDR ±12m 안에서 약한 재가중|기존 독립 재생에서 적용 빈도가 낮고 실제 개선 미확정|
|층 변화|알려진 시작 층 이후, 수직 연결부에서 상대기압 변화 후보를 처리|초기 층 자동 판별이 아니며 실제 계단·엘리베이터 검증 전|
|초기 위치|2층 19회·4층 16회 정지 기준점으로 층 입력 후 큰 구역 후보 분석 가능|정확한 노드·초기 층 자동 확정은 미구현이며 같은 기기 자료만 존재|
|4모드 기록|자유 위치 시험과 Android 일반 안내가 `derived_fusion`을 저장|일반 안내는 현장 정답 랩이 없으므로 동작 진단용|
|경로 라벨 기록|강의실·진입점·계단 랩, 센서/BLE, 기존 PDR와 모드 4를 같은 로그에 저장|정량 재평가 구조 완료, 새 2·4층 현장 로그 필요|
|지도 거리|4층 오른쪽 복도·코어 일부는 실측 반영|다른 층과 2·3층 증축부는 도식 좌표가 남아 있어 물리 m 오차로 평가 불가|

한 로그에 엔진 추정값과 현장 정답 라벨을 함께 기록하는 구조는 2026-09-19 Android schema 9로 구현했다. 이제 가장 먼저 해결할 문제는 **같은 조건의 2·4층 현장 로그로 모드 4가 기존 PDR보다 실제 오차를 줄이는지 판정하는 것**이다.

## 2. 제품 목표를 세 단계로 나눈다

### 단계 A — 같은 층 안내 파일럿

대상은 4층과 2층이다. 사용자가 현재 층·코어/계단/등록 진입점 중 하나를 확인하면 안내를 시작한다.

- 4층: 올바른 진행방향 유지, 복도 진행량, 계단/목적지 도착 판정 검증
- 2층: 메인복도 진행, 2107·책상공간·TDM 도착, 증축부 진입 포털 선택 검증
- 안내의 주 출력은 `직진`, `다음 진입구`, `안쪽으로 진입`, `목적지 근처` 같은 이산 상태와 랜드마크로 한다.
- 지도 위 이동 점은 진단용으로 유지하며 사용자 신뢰의 주 근거로 사용하지 않는다.

단계 A는 최종 자동 초기화 목표를 포기하는 것이 아니다. 자동 초기화와 층 이동이 준비되기 전에도 안내 핵심을 검증하기 위한 파일럿이다.

### 단계 B — 층간 안내 파일럿

- 시작 층은 사용자 확인 또는 외부→실내 진입점으로 초기화한다.
- 등록된 계단·엘리베이터 연결부에서만 상대기압 층 전이를 허용한다.
- 층 전이 중에는 수평 도착 안내를 멈추고 `층 이동 중` 상태를 표시한다.
- 새 층 도착 후 해당 층 연결 노드에서 수평 추적을 재개한다.

### 단계 C — 최종 사용자 흐름

- 사용자는 목적지만 검색한다.
- 외부 진입 정보 또는 내부 다중 후보가 시작 층·위치·방향을 추정한다.
- 불확실하면 잘못 확정하지 않고 층·가까운 시설 후보를 사용자에게 한 번 확인받는다.
- DEC-017의 무필수입력 목표는 유지하되, 자동 추정 실패 시 확인 UI를 정상 복구 경로로 둔다.

## 3. 분기와 구역은 연속 좌표가 아니라 상태로 관리한다

권장 상태 흐름은 다음과 같다.

```text
START_CONFIRMED
→ MAIN_CORRIDOR
→ PORTAL_APPROACH
→ BRANCH_CANDIDATE
→ BRANCH_CONFIRMED
→ DESTINATION_APPROACH
→ ARRIVED
```

- 포털 밖에서는 분기 후보를 만들지 않는다.
- `BRANCH_CANDIDATE` 동안 메인복도 후보와 분기 후보를 함께 유지한다.
- 분기축과 맞는 걸음이 3회 연속이고 분기 파티클 질량이 0.65 이상일 때만 `BRANCH_CONFIRMED`로 전환한다.
- BLE·자기장은 분기 확정의 단독 근거로 사용하지 않는다. 최소 6초 떨어진 관측이 같은 분기를 지지할 때 보조 근거로만 사용한다.
- 확정 후 반대 상태로 되돌리려면 등록 포털 통과 또는 3걸음 연속 반대 이동이 필요하다.
- 확신이 부족하면 화살표를 반대로 뒤집지 않고 `진입 여부 확인 중`을 표시한다.
- 휴대폰 방위가 1초 안에 45도 이상 변했지만 지도상 회전·걸음 순서가 맞지 않으면 방향 관측 가중치를 낮추고 기존 경로 상태를 유지한다.

수치는 첫 구현의 실험값이다. 아래 제품 게이트를 통과하지 못하면 조정하되, 같은 평가 로그에 맞춰 반복 튜닝하지 않는다.

## 4. 필수 로그와 지표

알려진 시작점 추적은 별도 시험 화면을 만들지 않고 기존 경로 라벨 수집 화면으로 수행한다. 랩 없이 걸으면 실시간 추적 확인, 선택한 중간 랩을 누르면 정량 평가가 된다. 앱은 모드 4를 주 예측으로 실행하고 기존 PDR 기준선을 내부 기록한다. 모드 2·3은 같은 파일의 원시 센서·BLE를 사후 재생해 비교한다. 자유 위치 시험은 시작점 미지정 초기화와 비정형 이동 검증에만 사용한다.

- 시험 조건: 익명 사용자 ID, 기기 모델, 시간대, 혼잡도, 휴대폰 자세, 선택 모드
- 엔진 출력: PDR/자기장/BLE/결합 위치, 상위 구역 후보, 파티클 질량, 분기 후보·확정 상태, 층 후보
- 현장 라벨: 시작점, 포털 접근, 실제 분기 진입, 중간 랜드마크, 계단/엘리베이터 탑승·도착, 목적지 도착
- 품질 이벤트: 방위 급변, 센서 누락, 구역 전환, 안내 방향 변경, 복구 발생

핵심 지표는 다음과 같다.

1. **분기 정답률**: 실제 분기 라벨과 확정 복도가 일치한 비율
2. **잘못된 복도 확정률**: 틀린 복도를 `CONFIRMED`로 만든 비율
3. **도착 오차**: 실측 구간은 m, 미실측 구간은 문 번호 차이
4. **구역 전환 튐**: 확정 이후 포털 통과 없이 안내 상태가 뒤집힌 횟수/분
5. **초기화 시간**: 시험 시작부터 시작 위치 확정까지 걸린 시간
6. **층 전이 성능**: 실제 층 도착 정답률, 도착 후 확정 지연, 같은 층 오검출
7. **불확실성 정직성**: 틀린 확정보다 `확인 중`을 출력한 비율을 별도로 기록

평균 좌표 오차는 보조 지표다. 분기·층·도착 실패를 평균에 섞어 숨기지 않는다.

## 5. 채택 기준

### 엔진 기능 채택 기준

모드 1 `PDR+지도`를 기본 기준선으로 둔다. 자기장, BLE 또는 결합 모드는 다음을 모두 만족할 때만 기본 엔진에 채택한다.

- 분기 정답률 `95% 이상`
- 잘못된 복도 확정률 `1% 이하`
- 도착 판정 `90% 이상`이 실제 문 기준 ±1문 이내; 실측 구간은 3m 이내
- 구역 전환 튐 `0.2회/분 이하`
- 기준선보다 중앙 도착 오차가 `15% 이상` 또는 `0.5m 이상` 개선
- 90백분위 도착 오차와 잘못된 복도 확정률은 기준선보다 악화되지 않음

개선량 조건을 만족하지 못하면 추가 가중치 튜닝을 계속하지 않고 모드 1을 파일럿 기본값으로 사용한다. 자기장·BLE는 진단 로그로 남길 수 있다.

### 평가 자료 최소 조건

- 사용자 3명 이상
- Android 기종 2종 이상
- 조용한 시간과 수업 교체 시간 각각 포함
- 정방향·역방향 포함
- 4층 완주 24회 이상
- 2층 실제 분기 통과 40회 이상
- 학습/튜닝 회차와 최종 평가 회차 분리

한 사용자·한 기기 결과는 엔지니어링 점검에는 사용할 수 있지만 제품 채택 근거로 사용하지 않는다.

### 층 전이 채택 기준

- 등록된 계단·엘리베이터 이동의 층 도착 정답률 `95% 이상`
- 평탄부 도착 후 `10초 이내` 층 확정
- 같은 층 30분 보행에서 잘못된 층 전이 `0회`
- 초기 층을 모를 때는 자동 확정 실패를 허용하되 틀린 층을 확정하지 않고 사용자 확인으로 복구

## 6. 지도 사용 기준

- 각 복도·포털·문 위치에 `현장 실측`, `GLB 정합`, `도면 비례`, `미확인` 상태를 둔다.
- m 단위 성능 평가는 `현장 실측` 또는 동일 기준점으로 정합된 GLB 구간에서만 한다.
- 도면 비례 구간은 문 번호 차이와 분기 성공 여부로 평가한다.
- 2층은 메인복도 중앙선의 2107 진입점, 책상공간 진입점, 기둥·TDM 사이 포털, 증축복도 중심선의 연결 순서를 먼저 검증한다.
- 지도 연결이 미확인인 구간에는 하드 벽·강제 스냅을 추가하지 않는다.

## 7. 다음 2주 우선순위

### 1순위 — 경로 라벨 수집에 모드 4 추적 연결

구현 완료. 실기기 설치와 2·4층 정·역방향 현장 검증이 남았다.

- Android 경로 라벨 수집 중 모드 4 `derived_fusion`을 실시간 계산한다.
- 화면에는 모드 4만 주 예측으로 표시한다. 기존 PDR 기준선은 내부 기록으로 유지하고 모드 2·3은 원시 로그 사후 재생으로 비교한다.
- 랩을 누르지 않아도 실시간 추적은 계속되며, 랩을 누른 경우 실제 위치와 모드 4 스냅샷을 정답 비교용으로 저장한다.
- 분기 후보·확정, 상위/차순위 구역 질량, 안내 상태 전환과 방위 급변을 로그에 추가한다.
- 같은 로그에서 모드 1~3을 재생해 현장 보행을 네 번 반복하지 않고 동일 센서 입력으로 비교한다.

### 초기 위치 시험 — 별도 평가

- 2층·4층 정지 기준점으로 층 입력 상태의 큰 구역 Top-1/Top-3와 잘못된 확정을 먼저 평가한다.
- Wi-Fi·BLE·자기장 정지 관측 뒤 5~10걸음 PDR를 추가해 후보가 수렴하는 시간도 측정한다.
- 현재 2층 Wi-Fi Top-1 75.0%, BLE 46.2%, 4층 Wi-Fi 84.6%, BLE 75.0%는 같은 Galaxy 정지 자료의 예비 결과다. 자동 시작점 확정 성능으로 해석하지 않는다.

### 2순위 — 4층 기준선 확정

- 코어→오른쪽/왼쪽 계단 정·역방향을 수집한다.
- 정상 파지뿐 아니라 화면 확인, 옆으로 돌림, 잠깐 주머니 넣기를 조건 라벨로 남긴다.
- 4층에서는 진행량·도착 오차와 안내 상태 튐을 본다. 분기 지표는 2층에서 평가한다.

### 3순위 — 2층 분기 상태 검증

- 2107 진입과 기둥·TDM 사이 증축부 진입을 실제 분기 라벨로 기록한다.
- BLE 신호가 아니라 포털 통과·걸음 방향으로 먼저 분기를 확정하고 BLE·자기장은 확인 근거로 비교한다.
- 책상공간 7걸음 중단본은 평가에서 제외하고 정상 완주로 다시 수집한다.

### 4순위 — 다사용자·다기기 시험

- 추가 사용자 2명과 추가 Android 기기 1종을 확보한다.
- 같은 경로·동일 라벨 순서로 수집하고 사용자·기기 회차를 분리해 평가한다.

### 5순위 — 층 전이

- 오른쪽 계단 내부와 엘리베이터를 각각 별도 시험한다.
- 알려진 시작 층에서 상대기압 층 전이부터 검증하고 초기 층 자동 판별과 섞지 않는다.

## 8. 당분간 하지 않을 일

- 정지 기준점을 더 촘촘히 만드는 일을 보행 성능 개선으로 간주하지 않는다.
- 미실측 지도의 도식 좌표를 실제 m 정답으로 사용하지 않는다.
- 네 모드 중 승자가 없는데 융합 가중치만 반복해서 조정하지 않는다.
