# Project Decisions

## DEC-036 AP는 기준점 접근 외 회전·불확실성에도 요청하되 지문 보정과 분리한다 (2026-10-02)

사용자가 합의했던 방향 전환 AP요청의 누락을 확인해 업데이트를 요청했다. 기존 DEC-023/DEC-026의 이동 중 AP제외·기준점에서만 요청 범위를 일반 안내와 자유 추적 모드4에 한해 변경한다. 경로 라벨은 시작/마지막 랩 AP만 유지하고 정지 기준지문 수집과 구분한다. 걸음을 동반한 지속 회전 또는 지속 추적 불확실성이 요청 계기이며, 이 계기를 코어/분기 도착 정답으로 취급하지 않는다. 한 사건은 우선1회, 새 지문이 부족한 경우 최대2회만 고려하고 앱 전체120초 최대4회 예산과 대기 잠금을 공유한다. OS제한/권한 실패를 계속 재시도하지 않는다.

새 AP의 최상위 후보가 실제 일치 조건과 현재 층/복도/15m이동 허용 범위를 함께 통과해야 한다. 멀리 있는 최상위 후보를 탈락시키고 덜 닮은 가까운 후보를 대신 받아들이는 동작은 금지한다. 미수집 구역은 중립, 단일 스캔은 기존 파티클 재가중만 한다. 움직이며 얻은 결과는 관측 시각·요청/응답 추정점·걸음 차이를 저장하고 낮은 품질로 쓰며 정확한 지연 궤적 재구성이나 현장 정확도 확보로 표현하지 않는다. AP를 끈 비교 조건, 기존 보폭·BLE·자기장 기본, 별도 m비교 버전을 유지한다. 현장 회전/지연·배터리·오보정 검증과 미연결8항목은 [합의 대조 문서](INDOOR_AGREEMENT_AUDIT_20261002.md)에서 추적한다.

## DEC-035 층별 추적 범위를 명시하고 m 좌표는 비교 가능한 선택 버전으로 유지한다 (2026-10-02)

사용자 요청에 따라 1층 메인입구 연결/공통 동선, 2·3층 등록 추가 연결, 4·5·6~10층 공통 메인복도·코어를 추적 범위로 정한다. 범위 밖은 실제 벽이라고 확정하지 않고 측위 범위 제외로 처리한다. 확인된 벽과 포털은 유지하며 새로운 문/벽 치수는 만들지 않는다. 계단은 진입과 상대 층 변화 상태로 다루고 평면 PDR를 중지한다. 계단참 정지로 층 이동 종료를 확정하지 않으며 상대 기압 층 후보+출구 확인 또는 검증된 층 비콘 입력이 필요하다. 실기기 검증은 별도다.

현재 공용 엔진과 지문·도면을 SHA 사본/ZIP으로 보존한 뒤 파티클·영역·관측 후보의 m 저장 좌표 버전을 분리했다. 기존 복도 PDR도 실측 거리표를 사용했으므로 단위 통일을 새 거리 측정이나 보폭 정확도 개선으로 해석하지 않는다. 같은11회 자료에서 m는 제약만 갱신한 기존 좌표보다 좋아지지 않아 기본 승격하지 않는다. 1층 길이 재사용·문별 위치·일부 폭의 측정 근거는 별도로 표시한다. 도면 비례로 미터 모드의 강의실 정답 좌표를 만들지 않는다.

신호 중심·걸음 보조는 검토 후보다. 현 자료의 AP 부재·BLE 비교 범위와 자기장 단독 후보 편향 때문에 PDR를 운영 기본에서 제거하지 않았다. 신규 비콘 설치 뒤 장소 확인과 신호 사이 이동량을 별도 평가한다. 근거와 구현/미구현 경계: `indoor/data/analysis/meters-20261002/REPORT.md`.

## DEC-033 BLE 앵커 신규파티클 제거와 AP unknown 보존 (2026-09-23)

사용자 승인에 따라 BLE 단일기준점 신호만으로 새좌표파티클을 생성하지 않고 약한 재가중을 유지한다. AP는 공통신호와 절대RSSI일치조건을 통과해야 보정하고, 미수집 후보를 제거하지 않으며 단일스캔은 좌표제안/재표집을 하지 않는다. 임계값은 unknown음성자료로 확정된 값이 아니므로 실험정책으로 기록한다. 고정보폭은비교기준/기본값유지, Weinberg와RoNIN은실험분리. RoNIN은PC11회추론완료했지만앱기본승격하지않는다. 상세: `indoor/data/analysis/radio-fix-20260923/REPORT.md`.

## DEC-032 왼쪽 왕복 지문 coverage 수정과 m_v 실험 분리 (2026-09-23)

사용자 요청에 따라 최신 왼쪽 정방향2/역방향3회로 만든173지문을 Android4층 왼쪽에 반영하고 좌우 복도 후보를 분리한다. 실제 거리표의 양 끝점으로 정렬하며 중간 보간을 약한 정답으로 표시한다. 모든 성능 평가는 회차 해시 제외 LOSO다. m_v는 비교 결과 일관된 개선이 없어 기본 활성화하지 않는다. 이는 누락 자료 수정이며 BLE 포함 전체 엔진의 우월성 확정은 아니다. 현재 원본과 이전 모델을 보존하고 legacy 생성기의 덮어쓰기를 차단한다. 상세: `indoor/data/analysis/left-magnetic-20260923/REPORT.md`.

이 문서는 프로젝트 진행 과정에서 발생한 중요한 기술·설계 결정과 변경 이유를 기록한다. 각 결정은 기존 상황, 확인된 문제, 결정, 이유와 현재 상태를 구분한다.

## DEC-003 2D와 3D의 기준 관계

### 기존 계획

2D 평면도를 먼저 구현하고 위치 안내가 안정화된 뒤 필요하면 3D로 확장한다.

### 변경된 상황

### 현재 결정

- 확정된 2D 지도를 구조와 좌표의 기준으로 사용한다.
- 3D 지도는 2D 구조를 시각화하며 독립적으로 구조를 변경하지 않는다.
- 코어와 계단 위치는 고정하고 강의실 이름·위치·크기는 층별 근거에 따라 조정한다.

### 이유

2D와 3D가 서로 다른 구조로 변하는 것을 방지하고 PDR·경로 좌표와 일관되게 연결하기 위해서다.

### 상태

적용 중, 현장 구조 최종 검수 필요

## DEC-006 실외·실내 위치 안내 전환 흐름

### 기존 범위

T-Beam GPS를 이용한 셔틀 위치 확인과 PDR 기반 실내 안내를 각각 검토했다.

### 확인된 문제

정류장에서 내린 사용자가 목적 단과대학 입구까지 이동하는 중간 구간의 측위 주체와 안내 방식이 빠져 있었다.

### 현재 결정

```text
버스 T-Beam GPS
→ 정류장 하차
→ 사용자 휴대폰 GPS로 건물까지 안내
→ 건물 진입
→ PDR·자기장·지도 정합 기반 실내 안내
```

### 이유

셔틀 위치 확인뿐 아니라 하차 지점부터 목적 강의실까지 끊김 없는 안내를 제공하기 위해서다.

### 상태

## DEC-008 실내 위치 추정과 보정 방향

### 기존 계획

PDR을 이용해 실내 위치를 추정한다.

### 확인된 문제

PDR은 이전 위치를 기준으로 보행거리와 방향을 누적하므로 걸음·보폭·방향 오차가 이동 시간에 따라 커질 수 있다.

### 현재 결정

PDR을 기본 위치 추정 방식으로 유지하고 자기장 특징과 지도 정합을 이용해 누적 오차를 보정한다. 기압계는 층 변화 판정의 보조 입력으로 검토한다.

```text
PDR + 자기장 기반 보정 + 지도 정합
```

### 검토 중인 대안

Wi-Fi RTT는 보조 측위 후보다. 건물 공유기와 휴대폰의 지원 여부 및 실제 정확도를 확인하기 전에는 기본 기술로 확정하지 않는다.

### 상태

기본 방향 확정, 실제 성능 검증 필요

## DEC-009 GPS 보정 방식은 데이터 분석 후 선정

## DEC-010 복도 연속 측정은 계단 입구를 종점으로 사용

### 기존 방식

4층 복도 연속 측정에서 양쪽 끝 강의실인 4204와 4128을 경로의 최종 도착점으로 사용했다.

### 확인된 문제

강의실은 길찾기 목적지이지만 복도 전체 측정의 물리적 끝점은 아니다. 층별·반복 실험을 비교하려면 쉽게 식별할 수 있는 고정 시설물을 종점으로 사용하는 편이 일관적이다.

### 결정

각 층의 측정은 `코어복도 출구 중앙점→오른쪽 계단 입구`와 `코어복도 출구 중앙점→왼쪽 계단 입구`로 구성한다. 이동 중 만나는 메인복도 강의실·공간은 지도 JSON의 x좌표 순서로 중간 랩을 생성하고, 계단 입구를 최종 도착 랩으로 기록한다. 왼쪽 메인복도는 위쪽 행을 우선 사용한다. 오른쪽은 2~5층에서 아래쪽 행, 1층과 6~10층에서 위쪽 행을 우선 사용하고 6~10층 아래쪽 행은 후속 반복 측정으로 추가한다. 본동 메인복도와 동선이 다른 증축부·야외공간은 별도 경로로 수집한다.

### 상태

Android 1~10층 수집 프리셋에 반영, 층별 현장 반복 측정 필요

## DEC-011 저층 증축부·야외공간과 3층 IT홀은 메인복도와 분리해 측정

### 확인된 문제

증축부와 야외공간을 코어→계단 메인복도 측정에 이어 붙이면 회전·우회 동선이 섞인다. 특히 3층 IT홀은 계단을 올라 ㄴ자 동선으로 진입한 뒤 다시 내려와야 하므로 3104 계열과 한 번에 측정하기 어렵다.

### 결정

## DEC-013 1층은 정문 진입을 기본 시작점으로 사용

### 기존 방식

### 확인된 문제

## DEC-017 최종 실내 안내는 시작 위치·방향 입력 없이 다중 후보를 자동 수렴한다

### 배경

DEC-014와 DEC-016의 층·기준점·방향 입력은 PDR, 기압, 지도 정합을 각각 검증하기 위한 통제 실험이다. 실제 사용자가 강의실을 검색한 뒤 현재 층, 현재 지점과 바라보는 방향을 직접 알려줘야 한다면 끊김 없는 위치 안내라는 최종 목표에 맞지 않는다. 또한 과거 절대기압만으로 시작 층을 즉시 고르는 방식은 실제 4층을 1층으로 오판해 사용할 수 없다.

### 결정

- 최종 사용자 흐름에서는 현재 층·시작 지점·최초 방향을 필수 입력으로 요구하지 않는다. 사용자는 목적지만 검색한다.
- 실외 안내에서 건물로 진입한 흐름과 건물 내부에서 앱을 처음 실행한 흐름을 서로 다른 초기화 시나리오로 처리한다.
- 외부 연속 안내에서는 휴대폰 GPS의 마지막 실외 위치, 건물 접근 방향, 기압·방위와 지도 진입 노드를 비교해 진입점 후보를 만든다. 지도상 진입 후보는 최소 `1층 정문`, `1층 좌·우 사이드계단`, `5층 야외 연결부`를 포함하며 이후 현장 확인에 따라 추가한다.
- 앱 실행 직후 외부/내부를 단일 GPS 샘플로 확정하지 않는다. `UNKNOWN → OUTSIDE → ENTRY_CANDIDATE → INSIDE` 상태를 두고 최근 GPS 위치·정확도 원, 건물 외곽 폴리곤, 접근 궤적과 연속 판정을 사용한다. GPS가 건물 내부에서도 남거나 튈 수 있으므로 경계 부근에서는 후보 상태를 유지한다.
- 1층 정문·양쪽 사이드계단과 5층 야외 연결부의 선택은 수평 GPS 진입 구역과 접근 방향을 주 근거로 하고 기압을 보조 근거로 사용한다. 1층과 5층의 기대 기압 차이는 현장 기준 약 `1.76 hPa`이지만 과거 절대기압표만으로 두 층을 판정하지 않는다.
- 첫 구현은 `1층 정문` 진입만 지원한다. 이는 구현 우선순위이며 건물의 유일한 진입점이라는 가정이 아니다. GPS만으로 출입문을 안정적으로 구분하지 못하면 지도에 표시된 정문 기준점에서 사용자가 `실내 안내 시작`을 누르는 통제 방식도 허용한다.
- 앱을 건물 내부에서 바로 실행한 경우에는 한 지점을 즉시 단정하지 않고 가능한 층·복도 노드·진행 방향의 다중 후보를 유지한다. 이동 후에도 후보가 충분히 수렴하지 않으면 잘못된 위치를 확정하지 않고 현재 층 또는 가까운 강의실·시설 등 최소 정보만 사용자에게 요청한다.
- 내부에서 정지한 경우에는 기존 로그의 라벨 시점 전후 자기장 `Btotal`, 지구 좌표계로 보정 가능한 자기장 성분, 방위, 기압과 센서 분산을 노드 지문으로 만들어 정지 관측과 비교한다. 현재 대부분 경로가 1회이고 단말별 편향도 있으므로 이 결과는 사용자 확인을 받기 전까지 위치 확정값으로 사용하지 않는다.
- 내부 초기 위치 UX는 `여기로 예상됩니다: 층·강의실/시설 후보`를 먼저 표시하고 `맞아요 · 안내 시작`과 `아니에요 · 현재 위치 선택`을 제공한다.
- 앱 실행 직후에는 위치 후보보다 먼저 `현재 건물 외부/내부에 계신 것으로 확인됩니다`를 표시한다. 사용자는 `맞아요 · 안내 시작`으로 판정을 확인하거나 `아니에요`를 눌러 `외부 / 내부` 중 실제 상태를 선택한다.
- 외부 확인 시에는 현재 GPS 위치에서 선택된 진입구까지 실외 안내를 시작한다. 내부 확인 시에는 정지 센서 기반 층·강의실/시설 후보 확인 단계로 넘어간다.
- 사용자가 예상 위치를 확인하면 해당 지도 노드를 현재 위치와 PDR 기준점으로 확정한다. 틀린 경우에는 자유 문자열 좌표 입력이 아니라 1~10층과 지도에 등록된 강의실·시설 검색으로 현재 위치를 선택한다.

## DEC-021 iPhone 신호 환경은 BLE부터 별도 조사한다

### 배경

iPhone은 일반적인 주변 Wi-Fi AP BSSID·RSSI 목록을 앱에 제공하지 않는다. Expo Go를 설치형 앱으로 바꿔도 이 제한은 사라지지 않는다. 반면 CoreBluetooth로는 근처 BLE 광고와 RSSI를 관측할 수 있으므로, 교내에 측위 보조에 쓸 만한 고정 송신기가 존재하는지 먼저 확인할 수 있다.

### 결정

- iPhone BLE 조사는 Expo Go 수집과 분리된 설치형 개발 앱에서만 실행한다.
- 층·구역 라벨별로 BLE RSSI를 원시 센서·자기장과 함께 수집하되, 주변 송신기가 실제로 고정·반복 관측되는지 분석하기 전에는 Fusion 보정이나 위치 앵커로 반영하지 않는다.
- JSONL에는 원시 BLE 식별자와 광고 이름을 저장하지 않고, 세션 간 비교 가능한 익명 ID와 RSSI·서비스 UUID 등 필요한 관측 특징만 저장한다.
- BLE가 충분히 안정적이지 않으면 PDR·자기장·지도 제약 기본 구조를 유지한다. 학교 Wi-Fi 인프라의 서버 측 위치 협력은 별도 검토 대상이다.

### 상태

로컬 iOS CoreBluetooth 모듈, 수집 화면과 EAS 개발 빌드 설정은 준비됐다. iPhone 실기기 설치·권한·스캔 및 신호 안정성 분석은 대기한다.

## DEC-022 신호 환경조사는 Android AP·BLE 동시 기준점을 우선 사용한다

### 배경

## DEC-023 이동 측위는 PDR·지도·자기장·BLE의 단일 사후분포로 비교한다
