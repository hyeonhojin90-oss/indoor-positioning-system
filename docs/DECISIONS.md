# 설계 결정 기록

## DEC-001 영역별 저장소 구조

- 결정: 프로젝트를 `gps`, `indoor`, `app`, `docs`로 분리한다.
- 이유: 4층 프로토타입 폴더가 다층 지도·센서 기능까지 포함하여 역할이 불명확해졌다.

## DEC-002 4층 공통 기준 데이터

- 결정: 4층 지도 데이터를 본동·코어 공통 기준으로 사용하고 다른 층은 오버라이드한다.
- 이유: 층별 공통 코어와 계단 축을 일관되게 유지하기 위함이다.

## DEC-003 2D와 3D의 기준 관계

- 결정: 3D 지도는 확정된 2D 지도에 근거하여 작성한다.
- 결정: 코어와 계단 위치는 고정하며 강의실 이름·위치·크기만 층별로 조정한다.

## DEC-004 대용량 파일 관리

- 결정: GLB, PDF, PNG, JPG, JPEG 파일은 Git LFS로 관리한다.
- 결정: 기존 Git 기록은 재작성하지 않고 현재와 이후 버전에 적용한다.

## DEC-005 진행상황 기준 문서

- 결정: 전체 상태는 `docs/CURRENT_STATUS.md` 한 곳에서만 관리한다.
- 이유: 여러 TODO·HANDOFF 문서가 서로 다른 시점을 가리키는 문제를 방지한다.
