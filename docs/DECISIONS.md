# Project Decisions

이 문서는 프로젝트 진행 과정에서 발생한 중요한 기술·설계 결정과 변경 이유를 기록한다. 각 결정은 기존 상황, 확인된 문제, 결정, 이유와 현재 상태를 구분한다.

## DEC-001 영역별 저장소 구조

### 기존 상황

4층 지도 프로토타입 폴더에 다층 지도, PDR, 자기장 자료와 도구가 함께 있었다.

### 확인된 문제

기능별 책임과 현재 상태가 불명확하고 작업 범위가 커질수록 파일과 문서 경로를 추적하기 어려웠다.

### 결정

프로젝트를 `docs`, `gps`, `indoor`, `app` 영역으로 분리한다.

### 기대 효과

각 작업의 책임, 전용 지침과 상태 문서를 분리하면서 전체 프로젝트 흐름은 루트 문서에서 관리할 수 있다.

### 상태

적용 완료

## DEC-002 4층 공통 기준 데이터

### 결정

4층 지도 데이터를 본동과 코어의 공통 기준으로 사용하고 다른 층은 층별 차이를 오버라이드한다.

### 이유

층별로 반복되는 코어, 엘리베이터와 계단 축을 일관되게 유지하면서 강의실 구조 차이만 표현하기 위해서다.

### 제한

4층 자료가 다른 층의 모든 구조를 증명하는 것은 아니다. 층별 피난안내도, 현장 사진과 사용자 설명을 추가로 확인한다.

### 상태

1~10층 지도 데이터에 적용됨

## DEC-003 2D와 3D의 기준 관계

### 기존 계획

2D 평면도를 먼저 구현하고 위치 안내가 안정화된 뒤 필요하면 3D로 확장한다.

### 변경된 상황

현재 1~10층 2D 지도와 단독·통합 3D 프로토타입이 모두 구현되었다.

### 현재 결정

- 확정된 2D 지도를 구조와 좌표의 기준으로 사용한다.
- 3D 지도는 2D 구조를 시각화하며 독립적으로 구조를 변경하지 않는다.
- 코어와 계단 위치는 고정하고 강의실 이름·위치·크기는 층별 근거에 따라 조정한다.

### 이유

2D와 3D가 서로 다른 구조로 변하는 것을 방지하고 PDR·경로 좌표와 일관되게 연결하기 위해서다.

### 상태

적용 중, 현장 구조 최종 검수 필요

## DEC-004 대용량 파일 관리

### 결정

GLB, PDF, PNG, JPG와 JPEG 파일을 Git LFS로 관리한다. 기존 Git 기록은 강제로 재작성하지 않고 구조 정리 이후 버전부터 적용한다.

### 이유

LiDAR·참고 이미지 원본을 저장소에 보존하면서 일반 Git 객체 크기 증가를 줄이기 위해서다.

### 상태

적용 완료, 20개 자료 등록 및 무결성 확인

## DEC-006 실외·실내 위치 안내 전환 흐름

### 기존 범위

T-Beam GPS를 이용한 셔틀 위치 확인과 PDR 기반 실내 안내를 각각 검토했다.

### 확인된 문제

정류장에서 내린 사용자가 목적 단과대학 입구까지 이동하는 중간 구간의 측위 주체와 안내 방식이 빠져 있었다.

### 현재 결정

```text
버스 T-Beam GPS
→ 정류장 하차
→ 사용자 휴대폰 GPS로 건물까지 안내
→ 건물 진입
→ PDR·자기장·지도 정합 기반 실내 안내
```

### 이유

셔틀 위치 확인뿐 아니라 하차 지점부터 목적 강의실까지 끊김 없는 안내를 제공하기 위해서다.

### 상태

아키텍처 확정, 전환 조건과 앱 구현은 검증 필요

## DEC-007 모바일 앱 Android 우선 개발

### 검토 상황

Android와 iOS를 모두 지원하는 앱을 목표로 하지만 현재 개발 환경은 Windows이며 iOS의 빌드·배포와 일부 센서·AR 검증에는 별도 조건이 필요하다.

### 결정

Android 앱을 먼저 개발하고 실제 기기에서 지도·센서·AR 핵심 흐름을 검증한다. iOS는 개발·배포 환경과 지원 기능을 검토한 뒤 지원 범위를 정한다.

### 이유

현재 환경에서 검증 가능한 구현을 먼저 확보하고 플랫폼 제약 때문에 전체 개발이 지연되는 것을 방지하기 위해서다.

### 상태

방향 확정, 앱 구현 전

---

## DEC-008 실내 위치 추정과 보정 방향

### 기존 계획

PDR을 이용해 실내 위치를 추정한다.

### 확인된 문제

PDR은 이전 위치를 기준으로 보행거리와 방향을 누적하므로 걸음·보폭·방향 오차가 이동 시간에 따라 커질 수 있다.

### 현재 결정

PDR을 기본 위치 추정 방식으로 유지하고 자기장 특징과 지도 정합을 이용해 누적 오차를 보정한다. 기압계는 층 변화 판정의 보조 입력으로 검토한다.

```text
PDR + 자기장 기반 보정 + 지도 정합
```

### 검토 중인 대안

Wi-Fi RTT는 보조 측위 후보다. 건물 공유기와 휴대폰의 지원 여부 및 실제 정확도를 확인하기 전에는 기본 기술로 확정하지 않는다.

### 상태

기본 방향 확정, 실제 성능 검증 필요

---

## DEC-009 GPS 보정 방식은 데이터 분석 후 선정

### 현재 상태

정식 T-Beam 원시 데이터셋과 오차 분석 결과가 없다.

### 결정

특정 필터를 미리 최종 방식으로 확정하지 않는다. 정지·이동 원시 데이터를 수집하고 오차, 지연과 품질 정보의 관계를 분석한 뒤 보정 방법을 선정한다.

### 이유

좌표가 부드러워지는 것과 실제 정확도가 향상되는 것은 다르며, 데이터 특성에 맞지 않는 필터는 지연이나 경로 왜곡을 만들 수 있기 때문이다.

### 상태

알고리즘 미확정, GPS 실험 대기
