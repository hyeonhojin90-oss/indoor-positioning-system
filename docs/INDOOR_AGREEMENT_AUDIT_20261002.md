# 실내측위 합의 사항과 실제 구현 대조 — 2026-10-02

대상은 현재 대화에서 사용자가 지시·동의한 실내측위 항목이다. 현재 공용 웹 엔진, Android 실제 소스, 설계 결정, 작업 기록, 실험 보고서를 함께 확인했다. 과거 보고서의 '미구현' 문장을 현재 상태로 그대로 옮기지 않았다. 제안만 나온 기능, 사용자 요청으로 미룬 작업, 현장 검증 부족을 구현 누락과 구분한다.

보고서 HWPX와 원시 센서 파일은 수정하지 않았다. 실외 GPS·승차 집계와 다른 대화에서 진행하는 작업은 이번 실내 감사에 포함하지 않는다.

## 이번에 확인해서 반영한 누락

| 계단 시작 위치도 공용 측량 기준선 사용 | 경로는 공용 기준선을 사용하지만 자유 추적 선택값은 화면에 상수로 남음 | 층 선택 시 공용 거리표의 입구선을 읽도록 연결. 현재 좌표에서는 오른쪽 입구가 x=3.363100346이며 실제 거리축의 0m와 구분 |
| 호실 판정은 엔진의 이동량 참조 결과 우선 | Android의 가까운 호실 표시는 도면 방 중심을 다시 검색 | 엔진에 반복 랩 정렬 기반 랜드마크가 있으면 그 이름·거리를 표시. 그림만으로 새 문 위치를 만들지 않음 |
| AP의 일치 조건과 거리 조건을 같은 후보에 적용 | 코어가 최상위 신호여도 코어가 멀면 낮은 순위의 가까운 계단을 대신 재가중할 수 있었음 | 최상위 AP 후보가 현재 층·복도·15m 조건을 통과해야 보정. 4층 후보별 점수≤2 적용, 대체 후보 우회 차단 검사 추가 |

### AP 요청 조건과 보정 조건

- 요청 계기: 기존 코어·양쪽 계단·오른쪽 계단 내부·2층 2204 근처·3층 3203~화장실 통로 사이 접근, 걸음 동반 방향 전환, 지속적인 추적 불확실성 중 하나.
- 최초 구현의 회전 설정은 기준 방향과 60도 이상 차이, 변화 방향이 0.8초 이상 유지, 변화 이후 검출 걸음 2개 이상이다. 0/360도 경계를 처리한다. 정지 회전과 계속 변하는 방향은 요청 확정으로 쓰지 않는다. 한 회전 묶음은 30초 내 중복 생성하지 않는다. 이 수치는 현장 최적화가 끝난 값이 아니다.
- 추적 불확실성은 현재 후보 질량 `modeWeight<0.55` 또는 `recovery_required` 상태가 4초 이상 이어질 때 요청 계기로 사용한다. 질량은 교정된 정확도 확률이 아니다.
- 한 사건에서 새 AP가 지문 비교·파티클 허용 조건을 통과하면 추가 요청을 하지 않는다. 부족한 경우에만 최대 두 번째 요청을 고려한다. 권한 실패·앱 예산 제한·OS 제한에 대해 반복 재시도하지 않는다. 오래된 사건은 45초 후 버린다.
- 일반 요청은 최근 120초의 3회까지만 소비하고 1회를 불확실성 요청에 남긴다. 직접 수집 버튼은 공통 최대 4회 제한을 따른다. 요청 간 최소 5초 간격, 공통 대기 잠금도 적용한다. 앱 재시작 후 OS의 이전 이력까지 앱이 재구성하지는 않는다. 실제 성공 여부는 OS 결과로 확인한다.
- 요청이 발생했다는 사실은 코어·계단·분기 도착의 정답이 아니다. 새 AP라도 기존 점수·차순위 격차·15m PDR 허용 범위·좌우 복도 보호 조건을 통과해야 보정한다. 최상위 신호 후보가 거리·복도 조건에서 탈락하면 하위 후보를 대신 받아들이지 않는다. 신호가 없는 구역은 중립으로 남기고 단일 AP로 새 위치 파티클을 만들지 않는다.
- AP별 관측 시각이 가장 최신 값에서 2초 이내인 항목을 융합에 전달한다. 이동 걸음 수로 품질을 낮추며, 과거 궤적을 정확히 다시 계산하는 지연 관측 필터까지 구현한 것은 아니다. 요청·응답 위치도 엔진 추정값이며 현장 정답이 아니다.
- 경로 라벨은 시작·마지막 랩 AP만 유지한다. 모든 중간 랩에서 자동 요청하도록 바꾸지 않았다. 마지막 랩 후 AP를 기다리지 않고 종료하면 미완료 스캔을 취소하고 즉시 저장한다.

Android 공식 제한 근거: [Wi-Fi scanning overview](https://developer.android.com/develop/connectivity/wifi/wifi-scan). 전경 앱의 2분 4회 제한은 30초마다 성공을 보장한다는 뜻이 아니다.

위 항목은 이번 AP 업데이트만으로 완료 처리하지 않는다. 나중에 ‘진행 상황’을 물었을 때 그대로 추적할 미완료 목록이다. 측량되지 않은 문·출구·비콘 위치를 임의로 만들지 않는다.
