# GPS Module

## 목적

버스 내부에 장착할 T-Beam으로 셔틀의 실외 위치를 수집하고, 실제 운행 환경의 GPS 오차 특성을 분석한 뒤 필요한 보정 방식을 적용한다.

이 영역은 셔틀 위치 GPS를 담당한다. 정류장에서 내린 사용자를 단과대학까지 안내하는 휴대폰 GPS 기능은 향후 `app/`에서 담당하며 두 위치 데이터의 출처를 구분한다.

## 현재 상태

- T-Beam은 셔틀 위치 추적용 목표 하드웨어다.
- 실제 사용할 T-Beam 모델, GPS 모듈, 펌웨어와 개발 환경은 확인 전이다.
- `firmware/uno-raw-test`에 Arduino UNO와 NEO-7M 기반 NMEA 원시 수신 시험 스케치가 보존되어 있다.
- 정식 T-Beam 원시 데이터셋, 파싱 코드와 보정 알고리즘은 아직 없다.

## 기본 작업 흐름

```text
T-Beam 환경 확인
→ GPS 원시 데이터 수신
→ data/raw에 원본과 메타데이터 저장
→ 정지·운행 상태 오차 분석
→ 보정 방식 선정
→ src에 보정 구현
→ data/processed에 결과 저장
→ 동일 원본으로 보정 전후 비교
→ 실제 셔틀 운행 환경 재검증
```

## 디렉터리

- `firmware/uno-raw-test/`: 현재 보존된 UNO·NEO-7M NMEA 수신 시험
- `src/`: 향후 T-Beam 데이터 파싱·분석·보정 코드
- `data/raw/`: 수정하지 않는 원시 측정 데이터와 수집 메타데이터
- `data/processed/`: 보정·필터링·분석 결과
- `tests/`: GPS 처리 코드와 데이터 검증 테스트
- `docs/GPS_DECISIONS.md`: GPS 기술 결정과 변경 이유
- `docs/GPS_STATUS.md`: GPS 파트의 현재 세부 상태
- `docs/GPS_TEST_PLAN.md`: 정지·이동·보정 비교 실험 계획
- `docs/GPS_RESULTS.md`: 실제 실험 결과 누적 기록

## 중요 원칙

- 실제 GPS 데이터를 분석하기 전에 특정 보정 알고리즘을 최종 방식으로 확정하지 않는다.
- 원시 데이터를 수정하거나 보정값으로 덮어쓰지 않는다.
- 동일한 원시 데이터로 보정 전후 정확도와 지연을 비교한다.
- 좌표가 부드러워졌다는 이유만으로 정확도가 향상됐다고 판단하지 않는다.
- 장치, 펌웨어, 날짜, 장소, 날씨, 측정 시간과 GPS 품질 정보를 함께 기록한다.

## 다음 시작점

1. 사용할 T-Beam의 정확한 모델과 GPS 칩을 확인한다.
2. Windows에서 가능한 빌드·업로드·시리얼 기록 환경을 확정한다.
3. 원본 NMEA와 사용 가능한 품질 필드를 확인한다.
4. 저장 형식과 첫 정지 상태 실험을 확정한다.
