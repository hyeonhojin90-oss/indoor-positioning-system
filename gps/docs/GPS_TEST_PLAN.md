# GPS Test Plan

## 1. 목적

T-Beam GPS의 실제 오차 특성을 확인하고 동일한 원시 데이터를 기준으로 보정 알고리즘 적용 전후의 정확도, 안정성과 지연을 비교한다.

## 2. 공통 준비

실험 전에 다음 정보를 확정하고 `GPS_RESULTS.md`에 기록한다.

- 테스트 ID
- 날짜와 시간대
- 장소와 이동 경로
- 날씨와 하늘 개방 정도
- 주변 건물, 수목과 전파 차폐 환경
- T-Beam 모델과 보드 버전
- GPS 칩과 안테나
- 펌웨어·코드 버전 또는 Git 커밋
- 샘플링·저장 주기
- 기준 위치 또는 기준 경로의 측정 방법

장치에서 제공되는 경우 다음 원시 필드를 저장한다.

- `timestamp`
- `latitude`, `longitude`
- `altitude`
- `speed`
- `course` 또는 `heading`
- `satellite_count`
- `HDOP` 등 품질 정보
- GPS fix 상태와 fix 종류
- 원본 NMEA

## 3. 데이터 관리

- 원본은 `gps/data/raw/`에 저장하고 수정하지 않는다.
- 보정 결과는 `gps/data/processed/`에 별도 저장한다.
- 원본과 결과 파일에 공통 테스트 ID를 사용한다.
- 보정 코드는 원본 파일을 덮어쓰지 않는다.
- 수신 중 누락, 파싱 실패와 fix 미확보 상태도 삭제하지 말고 상태값으로 남긴다.

## Test 1. 정지 상태 GPS 측정

### 목적

장치가 움직이지 않는 상황에서 GPS 좌표가 얼마나 흔들리고 기준 위치에서 얼마나 벗어나는지 측정한다.

### 방법

1. 측정 기준점을 정하고 가능한 방법으로 기준 좌표를 기록한다.
2. T-Beam을 같은 위치와 방향에 고정한다.
3. 초기 cold start와 충분히 fix된 상태를 구분한다.
4. 정한 시간 동안 원시 데이터를 연속 수집한다.
5. 가능하면 시간대와 환경을 바꿔 반복한다.

### 분석 항목

- fix 확보까지 걸린 시간
- 평균 위치와 기준 위치의 거리
- 평균·중앙·최대 거리 오차
- 표준편차와 위치 분산
- 좌표 튐의 횟수와 크기
- 위성 수·HDOP와 오차의 관계
- 시간이 지나면서 위치가 이동하는 드리프트

## Test 2. 이동 상태 GPS 측정

### 목적

실제 셔틀 또는 유사 이동 환경에서 측정 경로의 정확도, 연속성과 지연을 확인한다.

### 방법

1. 출발·도착 지점과 주요 회전·정차 지점이 있는 경로를 정한다.
2. 같은 경로를 가능한 한 여러 번 이동한다.
3. 실제 운행 속도와 정차 상황을 포함한다.
4. 개방 공간, 건물 주변, 수목 주변 등 환경 구간을 표시한다.
5. 비교 가능한 기준 경로와 주요 지점 통과 시간을 기록한다.

### 분석 항목

- 실제 경로와 측정 경로의 횡방향 거리 차이
- 순간 좌표 튐과 물리적으로 불가능한 이동
- 정차 중 좌표 흔들림
- 회전·출발·정차 반영 지연
- GPS fix 손실과 복구 시간
- 위성 수·HDOP 변화와 경로 오차
- 반복 주행 간 경로 재현성

## Test 3. 환경별 비교

### 목적

주변 환경이 GPS 품질과 오차에 미치는 영향을 확인한다.

### 비교 후보

- 하늘이 열린 공간
- 높은 건물 주변
- 건물 사이 또는 벽면 인접 구간
- 수목이 많은 구간
- 정류장과 실제 셔틀 내부

각 환경에서 측정 시간과 이동 조건을 가능한 한 동일하게 맞춘다.

## Test 4. 보정 전후 비교

### 원칙

동일한 `data/raw` 파일에 보정 후보를 적용해 비교한다.

```text
Raw GPS
vs
Corrected GPS A
vs
Corrected GPS B
```

### 평가 항목

- 평균·중앙·최대 오차
- 표준편차와 경로 안정성
- 순간 좌표 튐 감소
- 실제 경로 왜곡 여부
- 회전·정차 반응 지연
- GPS 품질 저하 구간의 동작
- 계산량과 실시간 적용 가능성

좌표가 매끄러워졌다는 이유만으로 정확도가 향상됐다고 판단하지 않는다. 오차 감소와 함께 위치 지연·경로 왜곡이 커지지 않았는지 확인한다.

## Test 5. 휴대폰 GPS 비교 실험

### 목적

정류장에서 단과대학 입구까지 사용할 휴대폰 GPS의 보행 안내 품질을 확인하고 버스용 T-Beam 데이터와 역할 차이를 기록한다.

### 확인 항목

- 휴대폰 모델과 운영체제
- 위치 권한·정확도 설정
- 정류장→건물 입구 보행 경로 오차
- 건물 접근 시 정확도 변화
- 업데이트 주기와 지연
- 건물 진입 판정 후보 신호

휴대폰 데이터는 T-Beam 원시 데이터와 별도 파일·장치 출처로 관리한다.

## 4. 완료 기준

- 원본 데이터와 실험 메타데이터가 함께 보존된다.
- 계산식과 평가 기준이 기록된다.
- 반복 가능한 실험 절차와 데이터 경로가 남는다.
- 성공 결과뿐 아니라 수신 실패, 오차 증가와 지연 조건도 기록된다.
- 보정 방식 선정 시 비교 결과와 선택 이유가 `GPS_DECISIONS.md`에 반영된다.
