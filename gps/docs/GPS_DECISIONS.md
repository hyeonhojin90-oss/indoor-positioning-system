# GPS Decisions

GPS 파트에서 선택한 하드웨어, 데이터 관리와 보정 방식을 이유와 함께 기록한다.

## GPS-001 셔틀 위치 추적 목표 하드웨어

### 결정

버스 내부에 T-Beam을 장착해 셔틀 위치 GPS 데이터를 수집한다.

### 현재 확인 수준

- T-Beam 사용 목적은 확정했다.
- 정확한 T-Beam 모델, GPS 칩, 핀 구성, 펌웨어와 통신 방식은 아직 확인 전이다.
- 현재 저장소에는 Arduino UNO와 NEO-7M 기반 NMEA 수신 시험 코드만 있다.

### 이유

장기적으로 버스 안에서 위치 수집과 무선 전송을 함께 수행할 장치가 필요하기 때문이다.

### 상태

목표 하드웨어 방향 확정, 세부 환경 미확정

## GPS-002 GPS 출처와 측위 주체 분리

### 결정

- T-Beam GPS 좌표는 버스 위치로 관리한다.
- 하차 후 휴대폰 GPS 좌표는 사용자 실외 위치로 관리한다.
- 두 좌표에 별도의 출처·장치·정확도·상태 정보를 기록한다.

### 이유

버스와 사용자는 정류장 하차 이후 서로 다른 위치에 있으므로 하나의 연속 GPS 궤적으로 취급할 수 없다.

### 상태

아키텍처 결정 완료, 데이터 스키마 구현 전

## GPS-003 원시 데이터 보존

### 결정

GPS 원시 위치와 가능한 경우 원본 NMEA를 보정 이후에도 유지한다. `data/raw`의 원본을 수정하지 않고 보정·가공 결과는 `data/processed`에 저장한다.

### 이유

동일 원본을 기준으로 보정 전후 성능을 재현하고 다른 알고리즘과 비교하기 위해서다.

### 상태

확정

## GPS-004 실험 메타데이터 필수 기록

### 결정

정식 실험에는 장치 모델, GPS 칩, 펌웨어·코드 버전, 날짜, 장소, 측정 시간, 샘플링 주기와 주변 환경을 기록한다.

### 이유

GPS 오차는 위성 배치, 건물·수목 차폐, 날씨, 장치와 설정에 따라 달라져 좌표만으로 결과를 재현하기 어렵기 때문이다.

### 상태

확정, 첫 정식 실험부터 적용

## GPS-005 GPS 필터링·보정 방식

### 현재 상태

미확정

### 후보

- 품질 기준과 물리적으로 불가능한 이동을 이용한 이상치 제거
- Moving Average
- Median Filter
- Kalman Filter
- 위성 수·HDOP·fix 상태 등 GPS 품질 기반 가중 처리
- 지도·도로 또는 셔틀 노선 정합

### 결정 방법

1. 실제 T-Beam 정지·운행 원시 데이터를 수집한다.
2. 기준 위치 또는 기준 경로와의 오차 특성을 분석한다.
3. 동일 원본에 후보 방식을 적용한다.
4. 평균·최대 오차, 표준편차, 좌표 튐, 경로 왜곡과 지연을 비교한다.
5. 프로젝트 요구에 가장 적합한 방법과 파라미터를 선택한다.

### 원칙

단순히 유명한 알고리즘이거나 좌표가 부드러워 보인다는 이유로 선택하지 않는다.

### 상태

실제 데이터 수집 대기
