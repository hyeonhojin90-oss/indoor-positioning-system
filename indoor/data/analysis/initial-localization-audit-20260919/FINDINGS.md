# 초기 위치 추정 자료와 추적 시험 구조 점검

작성일: 2026-09-19

## 결론

- 현재 자료로 **층을 알고 시작하는 2층·4층 구역 후보 분석**은 가능하다.
- 현재 자료만으로 **층과 정확한 시작점을 동시에 자동 확정**하는 것은 불가능하다.
- 알려진 시작점 추적 시험은 별도 화면을 만들지 않고 기존 `경로 라벨 수집`을 사용한다. 앱은 모드 4를 주 예측으로 실행하고 기존 PDR 기준선만 비교용으로 남긴다. 모드 2·3은 저장된 동일 원시 데이터로 사후 재생한다.
- Android 경로 라벨 화면은 현재 `FloorMapMatcher`의 기존 PDR만 표시한다. 별도 `FusionExperiment`의 4번 모드가 경로 라벨 기록과 연결된 상태는 아니다.

## 현재 초기 위치 자료

중복 파일을 SHA-256으로 제거한 Android 정지 기준점은 2층 19회, 4층 16회다. 모두 같은 Galaxy 기기 자료다.

|층|신호|독립 회차 평가 수|Top-1|판단|
|---:|---|---:|---:|---|
|2층|Wi-Fi AP|8|75.0%|큰 구역 후보 축소에는 사용 가능, 자동 확정에는 부족|
|2층|BLE|13|46.2%|단독 초기화 금지|
|4층|Wi-Fi AP|13|84.6%|코어·좌우 복도·계단 후보 축소에 유용|
|4층|BLE|16|75.0%|Wi-Fi/PDR 확인 근거로 사용 가능|

2층은 12개 구역 중 다수가 1~2회뿐이고, fresh AP가 없는 세션도 있어 Wi-Fi 평가가 8회에 그쳤다. 4층은 5개 큰 구역이라 상대적으로 분리가 쉽다. 위 값은 정지 상태·같은 기기 결과이며 보행 중 초기화와 다른 사용자 일반화를 증명하지 않는다.

기존 자기장 기반 초기 노드 모델도 분석 가능하지만 현재 Android 회차 제외 정확한 노드 Top-1은 10.3%(29회), iPhone 4층은 36.1%(36회)였다. 자기장 크기 하나로 정확한 방 앞을 선택하는 방식은 초기화 기본값으로 부적합하다.

## 가능한 초기 위치 시험

1. 사용자가 층을 입력한 상태에서 5~10초 정지 관측을 수집한다.
2. Wi-Fi, BLE, 자기장을 각각 순위화하고 `코어 / 왼쪽 메인복도 / 오른쪽 메인복도 / 계단 / 2층 증축 진입부` 같은 큰 구역 후보만 출력한다.
3. Top-1 점수 차가 작으면 확정하지 않고 상위 2~3개를 유지한다.
4. 걷기 시작 후 5~10걸음의 PDR 방향과 지도 연결로 후보를 줄인다.
5. 실제 시작 구역을 사용자가 한 번 선택해 정답을 남기고 초기 후보, 확정 시간, 오확정을 평가한다.

정확한 강의실 앞 초기화보다 `큰 구역 후보 → 짧은 보행으로 수렴`을 먼저 검증한다. 층 미입력 시험은 2·4층만의 같은 날 기압 차로 판단하지 않는다.

## 알려진 시작점 추적 시험

`경로 라벨 수집` 화면이 추적 시험이다. 시작점과 경로를 알고 시작한 뒤 랩을 누르지 않고 걸으면 **실시간 추적 확인**, 중간 랩을 누르면 **정량 평가**가 된다. 별도 추적 시험 화면을 만들 이유가 없다. 랩은 엔진을 움직이기 위한 입력이 아니라 실제 위치 정답이므로, 화면 동작 확인에는 없어도 되지만 사후 오차 계산에는 필요하다.

비교 대상은 다음 네 가지이지만 모두를 휴대폰에서 동시에 실행·표시할 필요는 없다.

1. 모드 1: PDR + 지도
2. 모드 2: PDR + 지도 + 자기장 8걸음 V2
3. 모드 3: PDR + 지도 + BLE
4. 모드 4: PDR + 지도 + 자기장 8걸음 V2 + BLE

화면의 주 예측은 모드 4만 표시한다. 기존 PDR인 모드 1은 화면을 복잡하게 만들지 않는 내부 기준선으로 기록할 수 있다. 모드 2·3은 가속도·자이로·방향·자기장·BLE 원시 기록으로 사후 재생한다. 랩을 누르지 않아도 모드 4의 실시간 위치는 갱신돼야 하며, 정량 평가 회차의 랩에는 실제 라벨과 모드 4 스냅샷을 저장한다.

모드 4는 가장 완전한 후보지만 아직 현장 정답 기준 최우수로 증명된 것은 아니다. 자기장 V2 적용 빈도가 낮고 이동 BLE 오판 사례가 있으므로, 모드 1 기준선과의 사후 비교에서 악화되지 않는지 확인한 뒤 안내 기본 엔진으로 확정한다.

## 현재 구현과 필요한 변경

- Android `MainActivity.kt`의 경로 수집은 센서 갱신마다 `floorMapMatcher.update()`를 호출하고 `현재 예측 · 기존 PDR`만 표시한다.
- Android 4모드 Fusion은 별도 `FusionExperiment.kt`와 WebView 런타임에서 실행하며 `derived_fusion`을 별도 파일에 저장한다.
- 따라서 현재 경로 라벨 화면에 보이는 예측은 4번 결과가 아니다.
- 다음 구현은 경로 수집 센서 스트림을 Fusion 런타임에도 전달하고 모드 4를 화면 주 예측으로 표시하며, 랩 레코드에 모드 4 스냅샷을 저장하는 것이다. 원시 센서·BLE와 기존 PDR 기준선은 사후 모드 비교가 가능하도록 계속 보존한다.
