# 지도 제약과 미터 좌표 분리 실험 — 2026-10-02

## 변경 범위와 보존

사용자가 정한 층별 이동 범위를 공용 navigation과 Fusion 런타임에 반영했다. 기존 엔진도 메인복도 진행량은 실측 거리표로 환산하고 있었다. 이번 미터 버전은 파티클 저장 좌표, 통로·벽·포털과 센서 후보 좌표까지 같은 m 단위로 다루는 별도 실행 모드다. 길이 측정을 새로 한 작업은 아니다.

변경 전 코드는 `exports/indoor-before-meters-20261002/`와 같은 이름의 ZIP에 보존했다. manifest의 SHA-256은 당시 positioning 코드·지도/지문 데이터·평가기·정렬 자료를 확인한다. 원시 JSONL과 Android 소스·설치 APK 전체의 백업은 아니다. 평가기는 기존 원시 로그를 저장소에서 읽는다.

## 지도 제약

| 층 | 이번 측위 범위 | 범위 밖 처리 |
|---|---|---|
| 1 | 메인입구 연결 공간 + 공통 복도·코어 | 쉬는 공간, 다른 입구·실외 경로는 제외 |
| 2 | 공통 범위 + 기존에 등록된 추가 영역과 진입 포털 | 강의실 내부는 제외. 책상공간/TDM 목적지는 기존 메인복도 접근 안내 유지 |
| 3 | 공통 범위 + 등록된 추가 영역 연결 | IT홀 연결은 미측정 초안 상태 유지 |
| 4·5·6~10 | 메인복도·코어·계단 연결 | 5층 실외 문을 통한 외부 추적은 제외 |

구간 전체를 검사해 등록되지 않은 공간이나 연결로 이동하는 후보를 차단한다. 이는 해당 공간에 실제 벽이 있다는 주장이 아니다. 이미 확인한 2층 벽·기둥의 통과 제한은 유지하며 새 벽을 측정 없이 추가하지 않았다. 코어는 세로 진행축을 사용한다. 지도 제약은 실제 계단·출구 진입을 감지하는 센서를 대신할 수 없다. 특히 5층 외부로 나간 사실을 확정하는 자동 판별은 추가하지 않았다.

계단 인근에서 상대 기압 변화가 나타나거나 검증된 진입 이벤트를 받으면 `vertical_moving`으로 전환하고 평면 PDR·자기장·AP/BLE 위치 보정을 멈춘다. 센서와 걸음 관측 자체는 계속된다. 잠시 기압이 안정되면 `vertical_floor_pending`과 층 후보만 기록한다. 계단참 정지를 층 이동 종료로 확정하지 않는다. 출구 확인과 상대 기압 층 후보가 함께 있거나 검증된 층 비콘 입력이 있어야 다시 추적한다. 이때 이전 자기장 창·BLE 창·방향을 초기화한다.

`RouteFusion.verticalEvidence(time, {verified:true, entryConfirmed:true})`, `exitConfirmed:true`, `beaconFloor:5` 입력 연결을 준비했다. 브라우저 모의 입력을 검사했으며 실제 비콘 식별과 Android 출구 확인 이벤트 생성은 아직 연결하지 않았다. 기압 0.44hPa/층과 코어 계단 인근 경계는 기존 임시 기준으로, 실기기 층 이동 시험이 필요하다.

## m 통일 전에 고려하고 처리한 문제

| 문제 | 처리와 남은 제한 |
|---|---|
| 보폭·후보 좌표에 m와 구도면 단위가 섞임 | 미터 모드 기본 이동량 약 0.6194m, 기존 좌표 입력은 경계에서 한 번 변환. 기존 도면 단위 보폭 회귀는 자동 적용하지 않음 |
| 자기장 V2·AP/BLE 앵커는 기존 좌표 자료 | 비교 지문 자체는 보존하고 후보 위치만 m로 변환. 실제 m인 거리 게이트를 다시 축척하지 않음 |
| 벽·진입점이 서로 다른 좌표계 | 공용 변환으로 영역·벽·포털을 함께 컴파일. 2/3층 추가 통로는 메인복도 축척으로 폭을 압축하지 않고 기존 지역 실측 변환으로 각각 약 3.701/2.059m 폭을 유지 |
| 추가 통로에서 x가 같아도 y 진행량은 다름 | AP·BLE 거리 게이트와 약한 가중치를 x 차이만 아닌 물리 x/y 거리로 계산. 같은 가로선이지만 23m 떨어진 진입점 후보 거부 검사 추가 |
| 지도 표시 좌표가 엔진에 역으로 섞임 | 엔진 `x/y`는 m. Android host `x/y`는 표시 좌표이고 `metricPosition`에 m를 별도 기록. 화면 좌표를 엔진에 다시 넣지 않음 |
| 강의실 문을 도면 비례로 정답화 | 4층은 반복 랩의 IMU 걸음 재검출을 시작·끝 실측 축에 정렬한 호실 후보 사용. 미터 모드의 다른 층은 그런 자료가 없으면 코어·계단만 제시 |
| 좌표 변환만으로 정확해진다는 오해 | 기존/제약만 변경/제약+m 변경 세 조건을 같은 원시 자료로 비교 |
| 전 층이 완전히 측량됐다는 오해 | 1층 공통 길이는 사용자 설명에 따라 재사용하며 별도 1층 측량은 아님. 코어 세로 치수·일부 폭·문 위치는 기존 근거 수준 유지 |

4층 호실 후보 19개는 표시 참고이며 보정 정답이나 새 물리 측량값이 아니다. Android 원시 걸음 카운터가 여러 랩에서 0 또는 같은 값으로 지연되는 것을 확인해 그대로 쓰지 않고 가속도에서 다시 검출했다. 그 걸음을 양 끝 기준선에 맞춰 평균 보폭으로 배분한 값이므로 중간 실제 보폭 변화와 버튼 시점 오차가 남는다. 호실별 회차 간 범위는 약 0.74~5.77m이다. 화면에서 가까운 후보를 보여주되 확정 문 위치라고 표시하지 않으며 이 표를 파티클 보정에 사용하지 않는다. 같은 11회로 만든 표시 표의 호실 정확도를 그 11회로 검증했다고 주장하지 않는다.

2/3층 추가 통로의 지역 실측 좌표는 등록된 진입축을 기준으로 배치했다. 지역 폭·깊이를 보존한 것이며 진입축의 메인복도 내 정확한 가로 위치를 새로 측량한 것은 아니다. 두 지역의 지도 표시 대응은 영역별 변환을 사용한다. 아직 측량되지 않은 연결부·방 폭을 완전한 전역 실측 평면도로 해석하지 않는다.

## 동일 자료 재생 결과

4층 Android 11회: 왼쪽 5회, 오른쪽 6회. 같은 원시 센서·시드·고정보폭 조건을 사용했다. V2는 평가 회차의 파일명/해시, 격자는 내용 해시를 제외했다. 오른쪽 8조건·왼쪽 4조건으로 버전당 68회, 세 버전 총 204회 재생했다. 새로운 현장 시험이 아니다.

| 버전 | 왼쪽 PDR 평균 종점 차이 | 오른쪽 PDR 평균 종점 차이 | 오른쪽 격자+V2+BLE 평균 종점 차이 | 해당 오른쪽 최대 |
|---|---:|---:|---:|---:|
| 변경 전 보존본 | 1.986m | 4.362m | 4.152m | 7.879m |
| 제약 갱신·기존 좌표 | 1.976m | 4.216m | 3.850m | 7.879m |
| 제약 갱신·m 좌표 | 2.002m | 4.280m | 4.053m | 7.873m |

제약 갱신본은 오른쪽 평균 차이가 작아졌지만 큰 오차는 남는다. m 버전은 제약 갱신·기존 좌표보다 오른쪽 융합 평균이 약 0.20m 더 크다. 좌표 변경에 따라 초기 분포, 영역 경계 검사와 파티클 선택이 달라지므로 결과가 완전히 같지는 않다. 개선된 엔진으로 승격할 근거가 없어서 m는 선택 실험으로 유지한다. 오른쪽 융합의 자기장 적용은 각각 16/15/14회, BLE 보정은 세 조건 모두 0회였다. 이 자료로 오른쪽 BLE 융합 성능이나 AP 성능을 입증할 수 없다.

오차는 알려진 시작선과 목적 기준선의 물리축에 대한 종점 차이다. 중간 강의실 문 위치는 독립 측량 정답이 없으며 보간값을 정확한 위치로 취급하지 않는다. 새 사용자·새 날·층 변화·1/2/3층에서의 현장 정확도는 이 시험 범위가 아니다.

## 신호 중심·이동량 보조 검토

같은 11회에서 위치·방향 PDR 게이트 없이 3초마다 BLE 5초 창과 자기장 2초 창을 비교했다. 층은 4층으로 주었고 지문은 측정 날짜가 다른 자료만 사용했다. 이 11회에는 AP 스캔이 0건이므로 AP 포함 신호 측위는 평가할 수 없었다. 자기장은 정지 지문 비교 진단이며 이동 자기장 격자 방식의 대체 성능 시험이 아니다.

| 입력 | 비교 시점 | 후보가 나온 시점 | 임시 점수·차순위 조건 통과 | 통과 후보 |
|---|---:|---:|---:|---|
| BLE | 197 | 25 | 8 | 전부 왼쪽 계단 |
| 자기장 | 197 | 182 | 38 | 전부 코어 |
| BLE+자기장 | 197 | 183 | 38 | 코어 37, 왼쪽 계단 1 |

공동 입력의 조건 통과 38개는 실제 유효 특징이 자기장만 37개, BLE만 1개였다. 두 신호가 함께 확인했다고 해석할 수 없다. 자기장 원 후보에는 반대 복도 후보 40개도 나타났고 임시 거부 조건에서 통과하지 않았다. 임계값은 독립 자료로 확정하지 않았으며 창들이 일부 겹친다. 위 수치는 위치 정답률이 아니다. 후보가 코어로 나왔다는 사실만으로 보행 중 실제 코어에 있었다고 결론 내리지 않는다.

따라서 현재 자료로 신호만 사용하는 운영 엔진으로 교체하지 않는다. 검토한 대안은 검증된 장소 신호로 위치/층 상태를 갱신하고 신호 관측 사이에는 걸음으로 등록 통로 진행량을 이어가는 방식이다. 휴대폰의 순간 회전을 경로 전환으로 즉시 쓰지 않고 통로 연결, 지속적인 이동·회전과 새 장소 신호를 함께 봐야 한다. 신호가 없거나 서로 다르면 위치를 확정하지 않아야 한다. 현재 격자는 PDR 주변 탐색과 오프셋 보정이 필요하고 V2도 방향·복도 조건을 사용하므로 그대로 신호 전용 엔진이라고 부를 수 없다.

고유 ID가 고정된 새 비콘을 실제 배치한 뒤 해당 장소 확인과 신호 사이 이동량 연결을 별도 후보로 비교하는 편이 적절하다. 모든 구역 지문 수집만으로 방향·이동 중간 위치 문제가 자동으로 해결되지는 않는다. 초기 층·구역 판별도 이번 알려진 4층 진단으로 검증한 것은 아니다.

## 사용·검증·다음 단계

- 기본 실행은 기존 좌표를 사용하고 새 제약만 활성화한다. `fusion-route-runtime.html?coordinates=meters`가 별도 m 버전이다.
- PC API: `IndoorRuntime.create(data, models, refs, {floor:4, x:70.804, y:0, coordinateSystem:'meters', inputCoordinates:'legacy'})`. 미터 좌표를 직접 줄 때 `inputCoordinates:'legacy'`를 붙이지 않는다.
- 자동 검사: 단위·제약·계단 141개, 브라우저 32개 확인, 기존 방향/AP/BLE/자기장 회귀 9개 도구, 경로 runtime·센서 bridge·2/3층 통행 검토 브라우저 검사를 통과했다. 브라우저 오류·실패 요청 없음.
- 표시 2D·3D 기하·원시 측정 파일은 이번 작업에서 바꾸지 않았다. 통행 범위 검토 화면은 추적 범위 제외와 실제 벽 차단을 구분하도록 설명을 수정했다.
- APK 재빌드·설치, 비콘 실물·기압 계단 현장 검증은 수행하지 않았다. 새 공용 코드가 기존 설치 앱에 자동 반영됐다고 주장하지 않는다.
- 다음은 2/3층 진입·왕복에서 제약 실패 여부와 계단 진입/출구 상태 시험이다. m 버전은 이 검증과 같은 세션의 방향 전환 비교 후 기본 승격 여부를 판단한다.

원자료와 수치: `comparison.json`, 각 버전의 `evaluation.json`, `signal-only-review.json`, `landmark-alignment.json`, `browser.json`.

복구하려면 다른 작업 변경을 보존한 뒤 백업 manifest에 포함된 파일 중 이번 변경 파일만 선택 복사한다. 저장소 전체를 일괄 덮어쓰거나 Git 변경을 되돌리지 않는다. manifest와 ZIP은 이번 작업 중 수정하지 않았다.
