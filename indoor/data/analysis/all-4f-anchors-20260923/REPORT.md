# 전체 4층 기준점 재평가 — 카카오톡 14시 파일 포함

기존 22회에 새 기준점 5회를 추가해 27회 확보. 중복 원본 6개 제거, 손상·라벨 충돌 1회 제외하여 26회 분석. 새 자료는 코어, 왼쪽 복도 4122, 왼쪽 계단, 오른쪽 복도 4209, 오른쪽 계단 순서다. 원본 라벨의 한글은 U+FFFD로 손상되어 있으며 zone_id와 숫자 4122/4209는 보존되었다. 실제 서 있던 문 앞은 메모 손상으로 검증할 수 없다.

새 파일 모두 약31초 정상 저장. AP는 왼쪽 계단 14:53:59만 fresh=false, 나머지4회 fresh=true. 왼쪽 계단 AP를 새 지문으로 넣으면 안 된다. 오른쪽 계단은 1걸음, 나머지는 0걸음. 새 파일 5개는 전부 정지 기준점이며 경로 시작/끝 AP 자동 수집 시험자료는 아니다.

회차 제외는 같은 날짜의 다른 회차를 학습에 남기고, 날짜 제외는 평가 날짜 전체를 뺀다. 같은 정확한 위치에 다른 날짜/회차가 없는 4122는 22회 분모에서 빠졌지만 **실제 분류에서는 4225로 나왔다**. 4122는 이전에 동일 위치 기준지문이 없어 후보 목록에 없었다. 따라서 이 결과만으로 4122와 4225의 신호 구분 성능을 판단할 수 없다. 실제 측정 복도는 사용자 확인 중이며 현재 저장값(main_left)과 다르면 라벨 정정이 필요하다.

오늘 새 5회 상세: AP 단독은 코어·4209·오른쪽 계단을 같은 위치로 선택, 왼쪽 계단은 새 AP 없음, 4122는 4225를 선택. BLE 단독은 날짜 제외 시 왼쪽 계단만 선택하고 나머지 4곳은 보류. AP+BLE 날짜 제외는 코어·왼쪽 계단·4209·오른쪽 계단을 맞췄지만, 4122는 역시 4225를 선택.

**중요:** 전체 회차 중앙값으로 계산한 진단이다. 현재 앱은 5초 BLE창과 단일 AP스캔으로 작동하므로 이 표를 실시간 성능이라고 단정하지 않는다. 미등록 복도의 오탐도 평가되지 않았다. BLE만 임계값을 낮추면 회차 제외에서 13회 오답이 난 문제를 키울 수 있다. 운영 지문/모델은 갱신하지 않았다.

## 2026-09-23 후속 수정
