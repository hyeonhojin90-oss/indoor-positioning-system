## 1. 판단

현재 프로젝트에는 센서 수집, 현장 랩, PDR, 지도 제약, 파티클 필터, 자기장 시퀀스, BLE·AP 지문과 Android 안내 연결이 이미 있다. 새 엔진 전체를 만드는 것보다 **물리 위치가 확인된 학습 지도와 공정한 재생 평가를 연결하는 일**이 우선이다.

보고서는 다음 흐름을 설계하는 자료로 유용하다.

`현장 앵커 → 오프라인 궤적 정렬 → 위치별 자기장 통계 → 기존 파티클 필터 관측 → 독립 회차 평가`

반면 포즈 그래프, 자기장 루프 클로저, GP 보간, 크라우드소싱을 동시에 추가하면 좌표 오류·특징 개선·지도 효과·평가 누출을 분리할 수 없다. 4층 오른쪽 복도의 1차원 거리 지도부터 검증하고, 2층은 연결된 복도 구간별 지도와 진입 상태를 확장하는 순서를 권한다. 3층과 다른 층의 일괄 확장은 현재 우선순위가 아니다.

## 2. 앞선 설명 중 정정·주의할 사항

### 2.1 67.4는 도면 축 차이이고, 채택된 물리 거리 기준은 50.193m다

현재 `floor-04-survey.json` 및 실행용 `areas-v1.json`을 읽어 `Nav.metricDistance`로 계산했다.

| 구간 또는 값 | 현재 기준 | 성격 |
|---|---:|---|
| 코어 쪽 벽 기준 오른쪽 복도 | 48.685453m | GLB에서 채택 |
| 코어 대향 벽 중심 사이 폭 | 3.015681m | GLB에서 채택 |
| 코어 중앙 → 오른쪽 계단 진입 전 메인복도 종점 | **50.193294m** | 48.685453 + 3.015681 / 2 |
| 같은 두 지점의 도면 x 차이 | 67.440900 | 미터가 아님 |
| 왼쪽 복도 길이 | survey 파일에 null | 기준 미확정 상태 |
| 각 강의실 앞까지의 실제 거리 | not_surveyed | 도면 값을 정밀 정답으로 쓸 수 없음 |

이 값은 사용자가 확인하여 채택한 GLB 기준이다. 이번에 레이저/줄자로 독립 실측했다는 뜻은 아니다. 종점은 사용자 설명대로 **계단 내부가 아니라 진입 직전 메인복도**다. 계단 내부 길이를 더하지 않는다.

거리 정합 코드 자체에는 이 기준이 존재한다. 그러나 과거 학습 도구는 오른쪽 종점을 x=0으로 놓고 강의실 도면 좌표를 읽는다. 실행 위치 이동이 수정됐다는 것과 모든 참조 템플릿·평가 좌표가 같은 버전으로 재생성됐다는 것은 다르다.

### 2.2 현재 자기장은 3축 원값 매칭이 아니다

`runtime.js`는 `Math.hypot(mx,my,mz)`인 자기장 크기 `|m|`를 사용한다. 보고서의 “3축 원값을 사용한다면”이라는 가정은 현재 코드에 해당하지 않는다. `m_v`는 기존 표현을 바로잡는 필수 교체가 아니라 **추가 정보가 있는지 검증할 새 특징**이다.

### 2.3 앞선 m_v 예비 결과는 실시간 성능 근거가 아니다

앞선 대화의 3회 Galaxy 예비 비교는 강의실 랩 부근 값으로 위치를 분류한 것이며, 8걸음 V2 또는 모드 4 전체 경로를 평가한 것이 아니다. 회차 전체 평균을 뺀 비교에는 질의 보행의 미래 값까지 사용됐다. 보고된 2.77→1.87은 미터 오차가 아니라 강의실 순서 차이 평균이었다. 이를 실시간 오차 감소로 표현하면 안 된다.

해당 임시 실험의 재현 코드·결과가 현재 정식 산출물로 보존돼 있지 않다. 이번 검토에서는 재실험하지 않았으며, **m_v에 정보가 있을 가능성을 보여 준 예비 관찰**로만 남긴다. 향후 과거/현재 창만 사용하는 전처리와 독립 회차로 다시 검증해야 한다.

## 3. 미흡한 점: 근거·영향·해결 방향

### A. 물리 거리·도면 좌표·학습 좌표의 일관성 — 최우선

근거:

- `navigation.js`는 도면↔지도 좌표를 구간별로 변환한다. 같은 x 차이라도 물리 거리가 항상 같지 않다.
- `train_motion_models.cjs`는 `manifest.json`, `ios_manifest.json`만 읽고 정방향 `CORE_TO_LEFT/RIGHT_STAIRS`만 허용한다. 오른쪽 계단 앵커를 x=0으로 만들며, 강의실 앞 도면 좌표로 랩 보간과 보폭 표적을 만든다.
- 배포용 `motion-models.json`에는 423개 템플릿, 원본 파일 11개가 있다. 템플릿 개수는 독립 보행 수가 아니다.
- 자기장 후보 제한에는 물리 거리 12m를 쓰지만, `observeSequence`의 가중치 폭은 `(p.x-c.x)/8`이라는 도면 축을 쓴다.

영향: 같은 데이터를 좌표계만 다르게 해석해도 학습 위치·보정 범위·평가 오차가 달라진다. 특히 새 격자 지도를 이 상태로 만들면 잘못된 간격을 더 촘촘하게 저장할 수 있다.

해결 방향:

1. 앵커별 `floor, edge_id, distance_m, display_x/y, 물리적 정의, 근거 파일/버전, 불확실성`을 단일 표로 관리한다.
2. 4층은 코어 중앙을 거리 0, 오른쪽 메인복도 종점을 +50.193294m로 표현할 수 있다. 화면 좌표는 별도 변환한다.
3. 학습·재생·실행이 동일한 물리 앵커 표를 읽게 한 뒤 템플릿을 재생성한다. 정·역방향을 모두 포함하고 이전 값은 버전별로 보존한다.
4. 실측하지 않은 강의실 앞 위치는 순서/근처 평가에 쓰고, 정확한 중간 위치 m 오차라고 부르지 않는다.

### B. 평가가 자기장 개선과 실제 측위 개선을 충분히 분리하지 못함 — 최우선

저장된 결과:

| 기존 실험 | 결과 | 해석 가능한 범위 |
|---|---|---|
| 과거 Galaxy 4층 3회 재생 | PDR 3.521m → 자기장 V2 3.518m; 32창 중 1창 적용 | 이 자료·약한 랩 좌표 기준에서 개선은 매우 작음 |
| iPhone 8걸음 후보 실험 | 100창 중 14창 통과; 통과 후보 중앙 차이 0.149m | 전체 경로 정확도가 아니며 실측 정답도 아님 |
| iPhone 같은 랩의 자기장 곡선 | 55회차 쌍 상관 중앙값 0.756 | 반복 구조는 있지만 위치 고유성/실시간 복구는 별도 |

`detailed-20260918/4f-magnetic-ablation/REPORT.md`의 수치는 당시 조건이다. 뒤에 BLE·AP와 안내 연결이 추가됐으므로 과거 ON/OFF 결과를 현재 모드 4 전체 성능으로 바꾸어 말하면 안 된다.

학습 자료에서 만든 지도를 같은 자료로 시험하거나, 질의 경로의 끝 랩을 이용해 질의 궤적을 먼저 펴면 정답을 미리 사용하게 된다. 전체 회차 평균으로 질의를 정규화하는 것도 실제 안내에서는 불가능한 미래 정보다.

해결 방향:

- 원본 파일 해시로 중복을 제거하고 회차 단위로 학습/검증을 나눈다. 동일 세션을 앞/뒤로 나누는 것은 독립 회차 검증을 대신하지 못한다.
- 지도 제작에는 학습 회차의 끝 랩까지 활용해도 된다. 시험 회차에는 시작점만 입력하고, 나머지 랩은 오차 채점에만 사용한다.
- 후보가 통과한 순간만이 아니라 전체 경로 오차, 적용률, 잘못된 보정률, 악화 회차, 복구 시간, 방향 반전/분기 오류를 함께 기록한다.
- 랩이 없는 연속 구간은 실제 좌표 오차를 알 수 없으므로 보간된 정답으로 정확도를 과장하지 않는다.
- 임계값 튜닝과 최종 시험을 분리한다. 표본이 적으면 검증 안쪽에서 튜닝하거나 값을 미리 고정한다.

### C. 2층 증축복도에 맞지 않는 전파 가중치 구조 — 우선 해결

`fusion-engine.js`의 `observeRadio`와 `observeWifi`는 후보 제한과 위치 가중치를 모두 `metricDistance(x)` 차이로 계산한다. 후보 파티클 생성에는 앵커 y도 사용하지만, 기존 파티클을 평가하는 전파 가중치에는 y 차이가 들어가지 않는다.

예를 들어 입구와 안쪽 2105 부근이 메인복도 방향의 x는 비슷하고 안쪽 방향 y만 다르면, 전파 후보를 인식해도 두 위치를 거리 가중치로 충분히 구분하지 못한다. 따라서 “안쪽에서 신호가 다르다”는 사실만으로 현재 엔진의 안쪽 진행량 보정이 완성되지는 않는다. 현재 자기장 시퀀스도 `main_right/main_left/core_junction/stairs` 구역만 지원하고 증축부는 제외한다.

해결 방향:

- 지도 상태를 `(층, 연결된 복도 구간, 그 구간에서의 진행거리)`로 표현한다. 메인복도와 증축복도에 같은 축을 억지로 쓰지 않는다.
- 전파는 연결 가능한 구간/구역 확률과 그 구간 내 진행거리로 반영한다. 벽 너머 가까운 점이 같은 후보가 되지 않도록 실제 연결 경로를 사용한다.
- 2층은 메인복도 PDR → 2204 부근 진입 후보 → 실제 회전·이동·BLE 등의 근거로 진입 확인 → 증축복도 내부 PDR+신호 순서를 유지한다. 목적지를 선택했다는 이유만으로 진입을 확정하지 않는다.
- 2107·책상공간·TDM의 메인복도 접근 안내라는 기존 요구는 유지한다. 책상공간 별도 경로를 다시 늘릴 이유는 없다.

### D. AP를 한 번 관측하는 정책과 큰 오차 복구 조건이 충돌 — 우선 해결

현재 안내 연결은 존재한다. `MainActivity.kt`에서 모드 4 추정값을 포함한 위치로 AP 기준점 진입을 판단하고, 새 결과를 `RouteFusionController`에 전달한다. “AP 개수 표시만 하고 보정에는 미연결”이라는 이전 상태는 현재 사실이 아니다.

다만 두 경로는 구분해야 한다.

- 일반 AP 약한 보정: 현재 추정에서 15m 이내 후보를 재가중하고 일부 파티클을 제안한다. 이것은 구현돼 있다.
- 큰 오차 복구: `recover()`는 신뢰 기준점에서 서로 다른 새 AP 관측 3개가 필요하고, 연속 관측 간격이 15초를 넘으면 다시 센다.
- `GuidanceApCoordinator`는 기준점 진입당 한 번만 요청한다. 같은 기준점 재진입은 최소 30초 간격이다. 따라서 이 요청 경로만으로 같은 기준점의 복구 조건을 충족하기 어렵다.
- `runtime.wifi()`는 15m 게이트를 통과한 약한 보정 뒤에만 `recover()`를 호출한다. 큰 이탈이 이미 15m를 넘으면 이 경로의 복구 진입 자체가 차단될 수 있다.

권장 수정은 AP를 무조건 빠르게 반복 요청하는 것이 아니다. 정상 추적의 단일 AP는 BLE·자기장·연결된 이동 경로와 함께 약하게 반영하고, 큰 이탈 복구는 별도 상태에서 독립 증거와 관측의 실제 나이를 확인하게 해야 한다. 복구용 관측 누적 조건은 실제 요청 가능 주기와 일치시켜야 한다. AP를 한 번 받았다는 이유만으로 위치를 강제 확정하는 것은 해결책이 아니다.

추가로 현재 계단 내부 요청 조건은 `matchedX/rawX`의 말단 임계값이다. 실제 계단 입구 통과·내부 진입을 확인한 것과 같지 않으므로 내부 자기장 지도에 그대로 정답 라벨로 쓰면 안 된다.

### E. m_v의 장점은 가능성이 있으며, 아직 성능 채택 근거는 부족함

`|m|`는 자기장의 전체 크기이고, `m_v = m · g_hat`는 중력 방향 성분이다. 같은 전체 크기라도 수직/수평 구성은 다를 수 있으므로 두 장소를 구분할 정보가 추가될 수 있다. 이상적인 회전에서는 둘 다 자세에 불변이다. 기존 크기 방식도 이미 회전에 불변이므로 “현재는 폰을 돌리면 무조건 깨지고 m_v로 해결된다”는 설명은 부정확하다.

필요 조건:

- 자기장과 중력을 같은 기기 좌표계·시각에 맞춘다. 중력 센서가 없으면 가속도 저역통과로 근사하되 걷기·회전·가감속에 의한 오염을 평가한다.
- 과거 데이터만 사용하는 창 정규화를 적용한다. 학습과 실행에서 동일하게 계산한다.
- 기기별 자기장 오프셋, 자성 케이스, 휴대 높이 차이를 별도 확인한다. 창 평균 제거가 모든 hard/soft-iron 오차를 제거하는 것은 아니다.
- 두 특징은 서로 관련 있으므로 독립 센서처럼 강하게 곱하지 않는다. 공분산 또는 보수적인 결합 강도를 검증한다.

Android 센서 정의 근거: [Motion sensors](https://developer.android.com/develop/sensors-and-location/sensors/sensors_motion). TYPE_GRAVITY는 3축 중력을 제공하지만 가속도에는 보행 가속도도 포함되므로 단순 저역통과 추정과 구별해야 한다.

### F. 학습·실행 경로 및 기록 관리의 재현성

- 과거 학습기는 가속도를 40ms 간격으로 간추려 기존 `positionTracking` 검출기를 사용한다. 실제 안내와 같은 걸음 시각이 나오는지 확인해야 한다. 센서 누락이 있으면 지도 정렬만으로 실제 걸음 패턴이 복원되지는 않는다.
- 정·역방향 참조와 신규 다운로드 파일의 포함 여부를 자동 목록으로 관리해야 한다. 현재 생성기의 정방향 정규식과 manifest 제한을 그대로 두면 왕복 자료가 있어도 지도에 빠질 수 있다.
- 정상 안내의 schema 9 센서·모드 4 기록과 경로 랩 연결은 소스에 구현돼 있다. APK 빌드 성공은 현장 정확도 검증이 아니다.
- 9월 19일 신규 4층 자료에는 원시 센서와 BLE가 있는 정상 왕복 4회가 있으므로 사후 재생 입력으로 활용할 수 있다. AP가 없는 경로에 AP가 있었던 것처럼 합성해서 전체 융합 성능을 주장하지 않는다.
- 불명확한 계단 내부 종료 랩, 0걸음 구간, 예전 라벨 오류는 원본을 보존하고 정답 앵커에서 제외하거나 사용자 확인 정정표를 적용한다. 센서 자료 전체를 폐기할 필요는 없다.

## 4. 보고서 항목별 활용 판단

| 제안서 항목 | 현재 있는 것 | 활용 방법 / 제한 |
|---|---|---|
| 클릭 앵커 | 현장 경로 랩, 시작점·종점 라벨 | 임의 도면 클릭보다 사전 등록된 물리 지점을 선택하는 현재 방식을 확장. 좌표·의미·불확실성 보강 |
| 앵커 기반 궤적 정렬 | `calibration.smooth()`의 진행량 비례 보간 | 별도 도구를 처음부터 만들 필요 없음. 물리 거리·회전 분할·검증 가능한 출력 추가 |
| 두 채널 자기장 | 자기장 크기만 구현 | m_v를 독립 실험하고 유효하면 채택 |
| 자기장 위치 지도 | 8걸음 템플릿과 구역 참조 | 4층 복도 거리별 통계로 확장. 기존 엔진에 관측으로 연결 |
| 파티클 필터 융합 | PDR·지도·자기장·BLE·AP 연결 존재 | 엔진 재구현보다 관측 좌표·분기 모델·복구 조건 개선 |
| 회차 제외 평가 | 기존 자기장 실험에 일부 있음 | 새 지도에서도 학습 지도를 매번 다시 만들며 동일 회차 전체 제외 |
| 자기장 루프 클로저 | 온라인 시퀀스 매칭 | 오프라인에서 서로 다른 경로의 같은 구간 후보를 찾는 데 재사용. 정답으로 자동 확정하지 않음 |
| 포즈 그래프 | 전체 최적화 도구 없음 | 4층 단순 직선은 보류. 2층 회전·여러 경로의 불일치가 남을 때 추가 |
| GP 빈 셀 보간 | 없음 | 먼저 무보간 지도 평가. 확인된 같은 복도 안에서 제한적으로 시험 |
| 자동 크라우드소싱 | 검증된 자동 갱신 체계 없음 | 후순위. 후보 지도·검증·버전/롤백을 갖춘 뒤 수동 승인부터 |

앵커 정렬은 “보행 때 누른 두 확정 지점 사이에 센서 값을 배치하는 것”이다. 시작·끝이 맞아도 중간의 걸음 누락/정지/보폭 변화는 정확히 분배할 수 없다. 양 끝 정렬 그림이 겹친다는 이유만으로 실제 궤적이 정확하다고 판단하지 않는다.

지도 생성용 교차 경로 매칭은 물리적인 교차로에 한정된 말이 아니다. 서로 다른 보행에서 같은 복도 구간을 지났는지 찾는 작업이다. 그 대응점이 맞으면 두 궤적의 늘어짐을 줄일 수 있지만, 비슷한 다른 구간을 연결하면 지도를 왜곡한다.

외부 구현도 활용할 수 있다. 필요한 경우 최적화는 SciPy의 `least_squares`, 보간은 scikit-learn의 GP 구현을 사용하고, 현재 파티클 필터와 로그 수집은 재사용한다. 직접 작성해야 하는 핵심은 우리 앵커의 물리적 의미, 로그/시간 동기화, 연결 가능한 복도 제약, 관측 신뢰도, 독립 평가다. 라이브러리가 이 프로젝트의 좌표 정답이나 잘못된 랩을 대신 판단해 주지는 않는다.

## 5. 보고서를 그대로 적용하면 위험한 부분

1. **상관계수 0.85는 정답 확률 85%가 아니다.** 전체 곡선이 비슷해도 여러 위치에 같은 모양이 반복될 수 있다. 최상위·차상위 위치의 차이, 왕복 일관성, 연결 가능성, 독립 회차에서의 오탐률을 확인해야 한다. 현재 V2는 정규화 DTW 점수를 사용하므로 0.85를 기존 임계값과 직접 대체할 수 없다.
2. **5m는 후보 검색 범위다.** 실제 오차가 5m를 넘으면 정답 후보가 빠질 수 있고 넓히면 오탐이 늘어난다. 검증에서 선택할 값이지 보편적인 기준이 아니다.
3. **1m 격자는 정확도 1m를 뜻하지 않는다.** 앵커 위치 오차·경로 정렬 오차가 2m라면 1m 셀에도 그 오차가 남는다. 셀별 실제 측정 여부·독립 회차 수·분산·좌표 불확실성을 저장해야 한다.
4. **GP 길이척도 2m는 주변 값이 얼마나 비슷하게 변할지에 대한 가정이다.** 벽 너머나 다른 층을 자동으로 보간하지 않는다. 같은 복도라도 급격한 자기장 변화는 매끈하게 지워질 수 있다. [RBF kernel](https://scikit-learn.org/stable/modules/generated/sklearn.gaussian_process.kernels.RBF.html)
5. **Huber 손실은 잘못된 연결을 자동 보증 제거하지 않는다.** 큰 잔차의 영향은 줄이지만 여러 오탐 연결이 함께 맞아 보이면 왜곡이 남는다. 연결 제거/검증과 독립 위치 평가가 필요하다. [SciPy least_squares](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html)
6. **BLE 상위 장치가 겹친다는 조건만으로 같은 위치가 되지 않는다.** 현재 4층 중간과 끝, 2층 인접 공간의 혼동이 저장된 분석에 있다. BLE는 보조 증거이며 루프 클로저 오탐을 확실하게 없애는 열쇠가 아니다.
7. **평균·분산 기반 관측에는 센서 잡음과 지도 오차도 필요하다.** 분산이 작다고 무조건 정확한 위치가 아니다. 복도 전체가 평평한 신호도 작은 분산을 가진다. 지역 반복성뿐 아니라 주변 위치와의 차별성을 평가한다.
8. **격자 한 점으로 바꾼다고 8걸음보다 반드시 좋아지지 않는다.** 패턴 정보가 사라져 비슷한 값을 가진 위치가 늘어날 수 있다. 공간 지도 위에서도 최근 관측의 순서를 사용하는 방법을 비교한다. 같은 자기장 샘플을 격자와 8걸음 항에서 이중으로 강하게 반영하지 않는다.
9. **파티클은 자동 복구를 보장하지 않는다.** 올바른 분기에 후보가 없거나 모두 사라지면 이후 좋은 관측만으로 복원되지 않을 수 있다. 분기 후보 유지·재생성·재탐색 상태가 필요하다. 미확인 통로를 벽으로 확정해 모두 제거하지 않는다.
10. **자유 보행 자기장 매칭을 곧바로 새 정답으로 쓰면 자기확증 오류가 생긴다.** 잘못 잡힌 위치를 기존 지도에 추가해 그 오류를 강화할 수 있다. 높은 파티클 수렴도와 낮은 정렬 잔차만으로 자동 채택하지 않는다. 별도 검증 지도와 이력/롤백을 유지한다.
11. **같은 형태의 층도 자기장·BLE 지도는 공유할 수 있다고 단정할 수 없다.** 구조는 재사용할 수 있지만 철재·설비·신호원과 기기/날짜 차이는 층별 검증 대상이다.
12. **300~400줄, 하루 구현, 층당 20분은 프로젝트 완료 근거가 아니다.** 제안서의 개략 추정이며 좌표 검증·로그 어댑터·실행 연결·오탐 평가 비용이 별도로 든다.

## 6. 권장 실험 순서

### 단계 0 — 기준선과 입력을 동결

현행 모드 4의 코드/지도/참조 버전과 시험 파일 해시를 기록한다. 각 회차에 플랫폼·기기·날짜·방향·사용 센서·정답 수준을 붙인다. 도면 좌표와 물리 거리를 통일하고, BLE·AP가 없는 파일은 해당 센서 실험에서 분리한다. 동작 변경 없이 기준선 재생부터 재현한다.

### 단계 1 — m_v만 추가한 비교

PDR, 지도, BLE, AP, 파티클 수/초기 상태, 난수 시드를 같게 두고 기존 8걸음 `|m|`와 `|m|+m_v`만 비교한다. 현 시점까지의 데이터로만 중력·창 정규화를 계산한다. 이 단계에서 8걸음 길이까지 동시에 바꾸지 않는다. 센서 누락/파지 회전 구간을 따로 본다.

### 단계 2 — 4층 오른쪽 복도 거리 지도

학습 회차의 실제 코어/종점과 신뢰 랩을 이용해 0~50.193294m 거리축에 자기장을 배치한다. 먼저 1m 간격의 프로파일을 만들되 표본이 없거나 불확실한 구간을 명시한다. 복도 양옆/미측정 공간을 채운 2D 전체층 지도로 가장하지 않는다. 같은 회차의 많은 샘플보다 독립 회차 수와 회차 간 편차를 우선 기록한다.

| 실험 | 자기장 관측 | 비교 목적 |
|---|---|---|
| E0 | 현재 8걸음 | 현행 모드 4 기준선 재현 |
| E1 | 8걸음 + m_v | 특징 추가 효과만 분리 |
| E2 | 거리별 지도, 자기장 크기만 | 지도 표현 변경 효과 |
| E3 | 거리별 지도, 자기장 크기 + m_v | 두 특징과 공간 지도 조합 |

E2/E3에서는 같은 자기장 시퀀스 항을 우선 끄거나 공통 관측 모델로 합쳐 중복 반영을 피한다. BLE/PDR 및 존재하는 AP 로그는 동일하게 유지한다. AP가 없는 경로에서는 “AP 포함 모드 4” 전체 검증이라고 부르지 않는다.

### 단계 3 — 회차 제외 평가

한 보행 회차 전체를 제외해 지도를 만들고 남긴 회차를 시작점만 알려 준 채 재생한다. 모든 회차를 차례로 시험하고 파일/날짜/방향별 결과를 낸다. 같은 날 같은 사용자 검증 결과는 다른 사람·다른 날 일반화와 구분한다.

필수 지표: 실측 종점의 부호 있는 진행 오차와 절댓값, 실측 앵커가 있는 중간 지점 오차, 미실측 강의실 순서 차이, 오보정 횟수/크기, 적용률, 회차별 악화, 정·역방향 차이, 유턴·분기 판단, 복구 지연. 표본이 적으므로 평균/P90만 보여 주지 않고 개별 회차도 제시한다.

현재 제품 목표 문서의 실측 3m 또는 ±1문 기준은 신뢰 가능한 실제 정답이 있을 때만 판정한다. 한 번의 평균 감소로 채택하지 않고 회차별 악화와 잘못된 확정을 함께 본다.

### 단계 4 — 2층 적용

메인복도 모델을 유지하며 증축복도에 별도 구간 진행거리를 만든다. 2204 진입 부근, 실제 기둥·TDM 사이, 2105-1 앞 같은 서로 다른 물리 지점을 구별한다. 기존 수집자료/GLB를 먼저 재검토하고, 없는 연결 거리와 불분명한 위치만 추가 확인한다. 분기 전후 후보와 신호가 실제로 구분되는지 검증한다.

### 단계 5 — 필요할 때 포즈 그래프와 자동 지도 확장

앵커 정렬 후에도 서로 다른 경로의 국소 왜곡이 반복될 때, 같은 구간 대응점을 추가해 최적화한다. 독립 평가에서 이득이 있어야 적용한다. GP 보간과 크라우드소싱은 이 다음이며, 자동 생성 후보 지도를 바로 운영 지도에 덮어쓰지 않는다.

## 7. 기존 자료로 가능한 일과 사용자 확인이 필요한 일

지금 PC에서 가능:

- 4층 오른쪽 거리·현장 라벨 재정합, 정·역방향/신규 파일 목록 정리.
- 자기장 3축과 가속도/중력 관련 필드가 있는 회차의 m_v 계산 및 신뢰도 진단.
- 기존 센서·BLE 보행의 동일 입력 모드 4 재생.
- 4층 1차원 자기장 지도와 회차 제외 평가. 추가 수집을 선행 조건으로 두지 않는다.
- AP 약한 보정/복구의 조건 충돌과 2층 좌표 관측 문제를 수정할 구체 사양 작성.

- 4층 왼쪽 복도: 현재 survey 파일에는 길이가 없으므로 이미 저장된 별도 GLB/실측이 있는지 먼저 찾는다.
- 중간 m 정확도를 주장할 필요가 있는 경우: 반복해서 식별 가능한 일부 중간점의 실제 거리만 확보한다. 강의실 전부를 다시 수집하라는 뜻이 아니다.
- 2층: 진입선과 안쪽 2105-1 등 앵커의 실제 연결 거리/기준 위치가 확인되지 않은 부분.
- 실제 계단 내부: 메인복도 앞 랩과 내부 종료 랩을 분리. 내부에서 마친 랩을 입구 귀환으로 해석하지 않는다.
- 이후 최종 일반화 검증용 다른 날짜/다른 사람 보행은 현행 자료로 할 수 있는 실험이 끝난 다음 최소 범위로 요청한다.
