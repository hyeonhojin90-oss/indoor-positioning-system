# 4층 오른쪽 복도 자기장 지도·m_v 회차 제외 평가

평가일: 2026-09-21

## 결론

합의한 1~4단계인 실제 거리 정렬, 현행 8걸음 기준선, `m_v` 비교, 1차원 자기장 지도 및 회차 제외 평가를 완료했다.

- 4층 코어 중앙부터 오른쪽 계단 진입 전 메인복도 종점까지 `50.19329386949539m`를 사용했다. 도면 x 차이 `67.44089965397924`는 미터로 사용하지 않았다.
- 완주 18회(iOS 14, Android 4)를 사용하고 2개 랩만 있는 Android 중단본 1회는 제외했다. 원본 SHA-256은 `evaluation.json`에 기록했다.
- 전체 회차에서 현재 고정보폭 PDR의 중간 진행 오차 평균은 `1.490m`였다. 8걸음 자기장 크기는 `1.548m`, 8걸음 자기장 크기+`m_v`는 `1.552m`로 전체 평균이 악화됐다.
- 0.5m 간격의 1차원 자기장 지도는 자기장 크기만 사용했을 때 `1.286m`(-13.7%), 크기+`m_v`일 때 `1.135m`(-23.8%)였다.
- 그러나 이 중간 오차는 양 끝 사이를 검출 걸음 순서로 나눈 **약한 정답**이다. 현장 실측 중간 좌표 오차가 아니다. 종점은 실제 앵커이므로 더 강한 근거다.
- `m_v`는 일관되게 이기지 않았다. 지도 방식에서 크기 단독보다 좋아진 회차가 18개 중 10개, Android는 4개 중 2개였다. 9월 19일 최신 Galaxy 정·역방향 두 회차에서는 모두 크기 단독 지도가 더 좋았다.
- 따라서 **자기장 지도는 후속 엔진 연결 후보**, **m_v는 지도에 함께 저장하되 기본 보정에는 아직 미채택**으로 판정한다. 앱·런타임 기본값은 변경하지 않았다.

## 평가 구성

| 기호 | 조건 | 구현 목적 |
|---|---|---|
| 기준선 | 고정보폭 PDR | 자기장 미사용 |
| E0 | 8걸음 자기장 크기, 기존 점수/간격 조건, 통과 시 25% 보정 | 현재 V2 방식의 물리 거리축 오프라인 유사 실험 |
| E1 | E0 + 수직 자기장 `m_v` | 기존 8걸음 방식에 `m_v`만 추가한 효과 |
| E2 | 0.5m 1차원 자기장 크기 지도 + 이산 위치 필터 | 자기장 지도 효과 |
| E3 | E2 + `m_v` 지도 | 지도와 `m_v`를 함께 쓴 효과 |

모든 시험 회차는 해당 회차 전체를 학습에서 제외했다. 지도와 참조 창은 같은 플랫폼의 나머지 회차로만 만들었다. 중간 강의실의 도면 좌표는 정답으로 사용하지 않았다.

E2/E3은 알려진 시작점 주변에서 시작하고 고정보폭으로 이동한 뒤 지도 관측으로 확률을 갱신한다. 첫 8걸음은 알려진 시작점 부근 지도와 비교해 해당 회차의 상수 센서 편차를 추정하는 데 사용한다. 질의 회차 전체 평균이나 미래 센서값은 사용하지 않는다.

`m_v`는 별도 중력 센서가 기록되지 않아 가속도 3축의 인과적 저역통과 벡터(시정수 1초)를 사용해 `m · ĝ`로 계산했다. 따라서 별도 `TYPE_GRAVITY`를 직접 기록한 결과와 동일하다고 볼 수 없다.

## 전체 결과

| 조건 | 중간 약한 정답 평균 | 중간 P90 | 실제 종점 평균 | 실제 종점 P90 | 종점 ±1m 도달 회차 |
|---|---:|---:|---:|---:|---:|
| 고정보폭 PDR | 1.490m | 4.183m | 1.239m | 2.665m | 10/18 |
| E0 8걸음 크기 | 1.548m | 4.500m | 1.130m | 2.117m | 10/18 |
| E1 8걸음 크기+`m_v` | 1.552m | 4.698m | 1.065m | 1.791m | 11/18 |
| E2 자기장 크기 지도 | 1.286m | 2.312m | **0.875m** | **1.025m** | **16/18** |
| E3 크기+`m_v` 지도 | **1.135m** | **1.931m** | 0.950m | 1.371m | 14/18 |

E3은 전체 중간 평균과 P90이 가장 낮았지만 E2는 종점 평균·P90과 ±1m 도달 회차가 더 좋았다. 현재 목적이 안내 도착 안정성까지 포함하므로 E3을 자동 채택할 수 없다.

회차별로 기준선보다 중간 평균이 낮아진 수는 E0 7/18, E1 8/18, E2 11/18, E3 12/18이다. 자기장 지도가 기존 8걸음보다 넓은 회차에서 작동했지만, 일부 정상 회차를 악화시키는 문제는 남는다.

## 최신 Galaxy 두 회차

| 회차 | 방향 | 걸음 | 기준선 중간 평균 | E2 크기 지도 | E3 크기+`m_v` 지도 |
|---|---|---:|---:|---:|---:|
| `20260919_111300` | 오른쪽 끝→코어 | 87 | 1.731m | **0.592m** | 0.642m |
| `20260919_111532` | 코어→오른쪽 끝 | 69 | 3.772m | **2.768m** | 2.911m |

두 회차 모두 자기장 크기 지도에서 개선됐고 `m_v` 추가는 조금 악화됐다. 정방향 69걸음은 E2를 사용해도 실제 종점에서 3.749m 부족했다. 자기장 지도만으로 걸음 검출/고정보폭 불일치를 완전히 복구하지는 못한다.

9월 1일 Android 1회는 검출 108걸음으로 기준선 중간 평균이 6.274m였고 E2가 7.152m로 악화됐다. E3은 5.831m로 기준선보다 낮지만 여전히 크다. 오래된 수집 방식과 현재 수집 방식의 걸음 검출 분포 차이를 하나의 자기장 지도로 덮는 것은 위험하다.

## 자기장 지도 품질

| 플랫폼 | 특징 | 지도 범위 | 셀 간 평균값 범위 | 셀 내부 표준편차 중앙 | 셀별 독립 회차 중앙 |
|---|---|---:|---:|---:|---:|
| Android | 자기장 크기 | 101/101셀 | 33.75µT | 7.72µT | 4회 |
| Android | `m_v` | 101/101셀 | 19.59µT | 7.35µT | 4회 |
| iOS | 자기장 크기 | 101/101셀 | 31.70µT | 2.71µT | 14회 |
| iOS | `m_v` | 101/101셀 | 22.95µT | 3.09µT | 14회 |

Android 지도는 모든 셀에 값이 있지만 끝 셀 일부는 독립 회차 1개뿐이고, 셀 내부 편차가 iOS보다 크다. 특히 `m_v`의 공간 범위 19.59µT에 비해 셀 내부 표준편차 중앙이 7.35µT라 구분력이 충분히 안정적이라고 보기 어렵다. iOS 지도는 반복성이 상대적으로 좋다.

## 무엇이 완료됐는가

1. **앵커 정렬 완료**: 각 완주 회차를 코어 0m와 오른쪽 종점 50.193m 사이에 검출 걸음 진행률로 배치했다. `aligned-sessions.json`에 걸음별 거리·자기장 크기·`m_v`를 저장했다.
2. **현행 기준선 완료**: 고정보폭 PDR와 8걸음 크기 참조(E0)를 같은 물리 축에서 계산했다.
3. **m_v 비교 완료**: 미래 값을 쓰지 않고 E1/E3에서 각각 별도로 비교했다.
4. **자기장 지도·회차 제외 평가 완료**: 플랫폼별 0.5m 지도와 18개 회차 제외 결과를 만들었다.

## 적용 판단

- **즉시 유지**: 기존 PDR·지도·BLE/AP 모드 4와 원본 수집 구조.
- **다음 구현 후보**: 4층 오른쪽 복도용 자기장 크기 1차원 지도. 단, 현재처럼 모든 관측을 반영하지 않고 주변 후보와 충분히 구분되는 순간에만 약하게 파티클을 재가중해야 한다.
- **실험값으로 보존**: `m_v`. 지도 파일에는 저장하되 Android 기본 가중치에는 아직 넣지 않는다.
- **아직 하지 않음**: 앱 런타임/학습 기본값 교체, APK 빌드, 2층 확장, 완전한 포즈 그래프 SLAM, GP 보간, 크라우드소싱.

다음 코드 단계는 E2 지도를 기존 파티클 필터에 **A/B 플래그로만** 연결하고, 위치 고유성이 낮은 구간에서는 관측을 거부하도록 신뢰도 게이트를 추가하는 것이다. E3은 별도 플래그로 유지해야 한다. 이 연결 후 같은 18개 파일을 실제 모드 4 전체 경로로 재생해, 이번 단순 이산 필터 결과가 실제 엔진에서도 유지되는지 확인해야 한다.

## 산출물과 재현

- `aligned-sessions.json`: 18회 거리 정렬 자료.
- `grid-4f-right.json`: 플랫폼별 자기장 크기·`m_v` 후보 지도. `runtimeDefault=false`이며 앱에서 로드하지 않는다.
- `evaluation.json`: 입력 SHA-256, 제외 사유, 회차별·플랫폼별 결과와 한계.
- 재현: `node indoor/tools/build_evaluate_4f_magnetic_map.cjs`

검증:

- 분석 도구 문법 검사 통과.
- 원본 해시 18개가 모두 서로 다름을 확인.
- Fusion 31개, motion-v2 15개, radio scan policy 테스트 통과.
- 앱·런타임 코드는 변경하지 않았으며 APK/현장 검증은 이번 단계 대상이 아니다.

## 한계

- 중간 진행 위치는 실제 바닥 좌표가 아니라 양 끝 사이 검출 걸음 진행률이다. 중간 평균은 방법 간 비교용이며 제품 정확도로 사용하면 안 된다.
- 같은 사용자·기기 계열의 자료다. Android는 4회뿐이다.
- 가속도 저역통과로 만든 중력 방향은 보행 동작에 오염될 수 있다.
- 지도 필터의 전이 분산·관측 강도는 이번 사전 고정값이며 최종 파티클 가중치가 아니다.
- 회차별 악화가 남으므로 평균 개선만으로 기본 엔진에 적용하지 않는다.
