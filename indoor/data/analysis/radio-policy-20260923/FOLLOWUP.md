# 2026-09-23 BLE 4개 및 자기장/AP 보정 검토

## 적용 범위와 재검증

BLE 관측창 유효 ID 수와 기준지문 공통 ID 최소조건을 모두 5→4로 변경했다. 지문 생성기 메타데이터도 동기화했다. 5초 창, ID당 2회 이상 관측, 3초 평가 주기, RSSI/coverage 점수와 파티클 거리 제한은 유지했다. APK 빌드/기기 설치는 이번 작업에 포함하지 않았다.

`node indoor/tools/audit_radio_policy_20260923.cjs`는 BLE 전용 조건을 교체해 5/4/3/2를 비교한다. Wi-Fi의 공통 2개 조건은 교체하지 않는다.

|9/22 입력|5개 후보 생성|4개 후보 생성|4개 결과|
|---|---:|---:|---|
|코어 정지|0/13|0/13|미판정|
|오른쪽 계단 정지|0/12|0/12|미판정|
|왼쪽 계단 정지 정정본|0/12|2/12|2개 모두 왼쪽 계단|
|왼쪽 계단→코어 보행|0/18|3/18|모두 왼쪽 계단 후보, 저장 예측 기준 거리 게이트 가능 1창|

중첩 관측창이며 독립 시험 정확도가 아니다. 보행 전 구간의 점별 정답이 없고, 전체 파티클 재생을 하지 않았으므로 보정 횟수/미터 오차 개선으로 해석하지 않는다. `test_ble_four_signal_gate.cjs`에서 관측 4개라도 공통 3개이면 탈락하는지, 런타임 3/4 경계를 검증했다. `test_wifi_anchor_fusion.cjs`도 통과했다.

## 왼쪽 계단 자기장: 환경 불일치로 단정할 수 없음

운영 `motion-models.json`의 Android 4층 지문은 direction=left 36개(지도 x=80.345~132.988), direction=right 88개(x=0.386~65.225)다. left에는 왼쪽 복도, right에는 오른쪽 복도 자료만 들어 있다. `runtime.step`은 heading으로 방향을 결정하고 `sequence.match`는 층/플랫폼/기기/방향으로만 지문을 고른다. 복도 구역 필터는 없다.

9/22 211757 왼쪽 계단→코어 로그에 남은 9개 자기장 진단의 상위 후보는 모두 오른쪽 복도 x 범위다. 즉 현재 자료 구성에는 이번 왼쪽 역방향을 제대로 비교할 지문이 없다. 기존 보고서의 ambiguous_sequence는 그 상태에서 나온 판정이다. 자기장 환경 자체가 변했다는 근거는 아니다.

9개 모두 최선 score는 0.0143~0.1369로 0.5 이하이지만, 다른 위치 후보와 margin은 0.00236~0.06155로 요구 0.08 미만이었다. 예: 첫 진단 score 0.0434와 0.0505, margin 0.0071. 형태는 여러 곳과 비슷했고 구별력이 부족했다. 정규화 과정은 평균과 크기를 제거하므로 절대 자기장 차이를 후보 구분에 쓰지 않는다.

우선 조치는 기존 왼쪽 왕복 로그로 물리 거리 앵커 정렬 후 방향별 지문을 다시 만들고, 좌우 복도/방향 coverage를 검사하는 것이다. 반대방향은 배열을 뒤집는 것만으로 검증 완료 처리하지 않는다. 후보 없는 구간은 명시적으로 no_reference로 표시한다. 최신 시험 회차를 학습에 넣고 같은 회차 성능을 보고하지 않는다. 이번에는 자기장 모델이나 임계값을 변경하지 않았다.

## 공동 점수 제안: 아직 운영 적용 아님

각 위치 후보에 대해 센서별 관측 오차를 정규화하고, 시간 및 신뢰도 계수로 완화한 로그우도를 PDR 사전분포에 한 번씩 합산한다. 실제 확률로 교정되지 않은 현재 상대 weight를 정확도 %로 표시하지 않는다.

- AP/BLE: 공통 ID RSSI 차이, 반복 측정 분산, 공통 비율, 안정 ID 비중으로 우도를 계산한다. ID 개수만으로 강한 가중치를 주지 않는다.
- 자기장: 올바른 복도/방향의 격자 또는 V2 중 하나를 사용한다. 기준값 offset, 분산, 구간별 구별력을 고려한다. 지문 없는 경우 기여는 0이다.
- 품질: 오래된 관측/스캔 중 이동량/센서 불안정성에 따라 낮춘다. AP와 BLE, 중첩 BLE 창의 상관성을 무시하고 반복 증거로 곱하지 않는다.
- 가중치 실험 후보: AP 0.5/1, BLE 0.15/0.3/0.5, 자기장 0.3/0.6/1. 서로 비교 가능한 우도 척도를 만든 뒤 회차 제외 검증에서 잘못된 강한 보정 수와 최악 오차를 우선, 평균 오차를 다음으로 평가한다. 확정 가중치가 아니다.
- 기준점 식별과 복도 내부 미터 진행량은 별개다. 코어 신호와 일치해도 즉시 코어 한 점으로 옮기지 말고 구역 분포를 반영한다.

## AP 요청 시점 제안: 현재 위치를 알아야만 요청하는 순환 제거

요청 계기와 보정 채택 조건을 분리한다. 기준점 근처 예측은 여러 요청 계기 중 하나일 뿐 필수조건이 아니다.

1. 시작 위치 불확실 / 보행 중 지속적인 방향전환 / 센서 간 위치 불일치 / 추정 분포 확대 / 기준점 접근 중 하나가 발생하면 요청 후보를 만든다. 휴대폰 회전은 실제 이동 방향과 다를 수 있어 걸음·회전 지속·이후 진행으로 보강한다.
2. 첫 AP는 회전 사건에서 1회 요청한다. 확실하면 종료하고, 애매하고 추가 정보 가치가 있을 때만 두 번째 요청을 고려한다. 한 사건 최대 2회는 OS 예산과 별도로 제한한다.
3. 앱 전체 최근 120초 요청 이력을 공유해 전경 4회 제한을 지킨다. 일반 이벤트는 예산 일부를 사용하고 위치 상실/층 전이에 예비 1회를 남기는 정책을 실험한다. 백그라운드는 별도 제한을 따른다. 30초는 OS 고정 간격이 아니다.
4. Android 10+의 다른 앱/시스템이 만든 새 스캔 완료도 수동 관측할 수 있다. 성공/타임스탬프로 새 결과를 구별하고 캐시 재수신을 새 증거로 세지 않는다.
5. 1회 스캔도 여러 AP의 RSSI 벡터라 공동 보정 근거로 쓸 수 있다. 단독 강한 위치 재설정은 별도 검증이 필요하다. 스캔 시각에 해당하는 PDR 위치/불확실성에 연결하며 수신 시점의 좌표에 무조건 붙이지 않는다.

현재 자유시험은 AP 요청원이 없고 일반안내는 예측 앵커 진입에 묶여 있다. 강한 복구의 3회/15초 조건은 일반안내 요청 정책과 맞지 않는다. 이를 단순 1회 리셋으로 바꾸지 말고 신선한 1회 AP와 같은 시공간의 BLE/자기장 공동 증거를 평가하도록 연결해야 한다. AP 스케줄러와 공동 판정은 제안 단계다.
