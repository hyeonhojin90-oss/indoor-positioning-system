# 구역·영역 기반 실내측위 v1 비교 실험

2026-09-07. 전체 진행상황은 `docs/CURRENT_STATUS.md`, 결정은 DEC-018을 따른다.

## 이번 버전의 범위

기존 1차원 PDR을 대체하지 않고 Expo 자유 추적에 **같은 센서의 병렬 비교 결과**를 연결했다. 새 결과는 `derived_fusion`으로 기록하며 실측 정답이나 자동 안내 확정값이 아니다. 지도 2D·3D 원본 형상, 기존 경로·랩·기압 수집, 원시 JSONL과 채택/제외 manifest는 유지한다.

Android는 2층 수집 프리셋과 좌우 구역 라벨을 수정했다. **Android 네이티브 추적기를 새 파티클 엔진으로 교체하지 않았다.** 공용 JS·JSON은 기존 웹 자산 경로를 통해 APK에도 포함되지만 파일 포함과 네이티브 센서 연결은 다른 단계다.

## 모듈과 계약

공용 구현은 `indoor/web/src/positioning/`에 있다. CommonJS(Node/Metro)와 브라우저에서 같은 소스를 사용한다. 외부 프로젝트 코드를 복사하지 않고 논의한 개념을 재구현했다.

| 파일 | 입력 → 출력 | 적용 수준 |
|---|---|---|
| `navigation.js` | 공용 영역 JSON, 두 좌표 → 통과/미확인/확정 벽 충돌 | 2·3층 세부 영역 + 1~10층 공통 복도 초안 |
| `zone-classifier.js` | 시각·플랫폼·자기장/새 AP 관측·참조 지문 → `(층, 구역)` 상대 점수 | 구역별 최근접 3개 거리 평균; 정답 확률 아님 |
| `fusion-engine.js` | 초기 후보, 방위, 걸음, 구역 점수 → 가중 파티클 위치 분포 | Expo 비교 실행, 기본 160개, 재현 가능한 seed |
| `vertical-tracker.js` | 기압·시각·수직 연결부 맥락 → 상대 층 상태 | 초기층 필요, IT홀 층내 변화 제외, 현장 미검증 |

- 자기장 관측은 비중첩 약 2초 창의 Btotal 중앙값·변동을 사용한다. 현재 순차 패턴 정합(DTW 등)이 아니라 **짧은 창의 구역 점수**다.
- 현재 앱 참조는 기존 플랫폼별 정지 노드 지문을 복도/코어/계단 입구로 묶은 약한 라벨이다. 전용 구역 지문 수집·모델 검증 완료를 의미하지 않는다. 이전의 불명확한 `강의실 라인` 라벨에 좌우를 소급해서 붙이지 않는다.
- 새로운 엔진에서 Galaxy 자기장 원시값을 iPhone 값으로 직접 합치지 않는다. 기존 자동 초기화의 실험적 기기 변환 후보는 보존하지만 새 구역 관측은 플랫폼별 참조를 사용한다. 세부 기기별 보정은 추가 과제다.
- Wi-Fi는 BSSID RSSI 교집합 2개 이상, fresh 표시, 관측 시각 유효성을 요구한다. 미지원·권한 누락·오래된 스캔은 AP 0개 증거와 다르다. 같은 스캔 시각에 새 이벤트 ID만 붙여 반복 가중하지 않는다. 혼합 관측에 이미 반영한 입력이 있으면 해당 창 전체를 보수적으로 생략한다.
- 구역 점수는 파티클에 한 번만 반영하며 같은 자기장 창을 위치 우도로 다시 곱하지 않는다. 표본 수 많은 복도 클래스가 단순히 표본 수 때문에 유리하지 않도록 구역별 거리 평균을 쓴다.
- 파티클은 `(floor,x,y,weight,strideScale,headingBias)`를 가진다. 대표 위치는 가장 큰 **같은 층·구역 모드 내부 평균**으로 표시하여 서로 다른 층/벽 양쪽 위치를 하나로 평균 내지 않는다. 내부 가중치·퍼짐은 교정된 신뢰도나 미터 정확도가 아니다.
- 방위 355°를 지도 오른쪽(-x), 265°를 코어→메인(+y)의 임시 축 기준으로 사용한다. 사용자 관측 약 350/175/270°를 근거로 한 가정이며, 기기 자세가 보행 방향과 다른 주머니 모드 등은 아직 지원하지 않는다. 방위가 오래되거나 없으면 새 엔진은 이동 방향을 지어내지 않고 대기한다.
- 보폭은 기존 `70.804/81` 지도단위 기준을 유지한다. cadence·가속도 peak 입력과 검증된 개인 회귀 계수의 ±20% 제한 인터페이스만 준비했다. 실제 학습 모델·실측 보폭이 없으므로 회귀는 비활성이다. 걸음 과검출 문제도 별도 평가해야 한다.
- 확인한 벽을 가로지르는 후보는 이동하지 않고 낮은 가중치로 남긴다. 대부분 충돌하면 복구 필요를 표시한다. 미확인 공간은 삭제하지 않고 낮은 가중치로 유지한다. **AP 앵커 자동 재초기화/완전한 추적 손실 복구는 아직 없다.**

## 2·3층 통행 모델

`indoor/web/data/navigation/areas-v1.json`은 지도에 덧붙인 측위용 데이터다. 원본 강의실 그림을 다시 제작하지 않았다.

- 2층 `메인→2107→M-space`와 `메인→기둥·TDM 옆 진입구→책상 또는 증축부`를 분리했다. 확인된 2107/책상 사이 벽과 기둥만 hard 제약이다.
- 3층 메인→진입구→자유공간→증축부, 자유공간→IT홀 계단→회전 연결부→IT홀을 초안으로 표시한다. IT홀의 정확한 회전점·문 폭/위치는 미확인이다.
- 연결부 선을 통과하는지는 영역 전환과 함께 검사한다. 표기된 연결부 밖의 전환은 곧바로 벽으로 간주하지 않고 `unverified_connection`으로 남긴다.
- 교차점은 코어 폭을 가진 영역이다. 지나갈 때마다 가운데 점으로 강제 스냅하지 않는다.
- SVG 도면은 균일 실측 축척이 아니다. 좌우 끝 및 코어 도면 x=690/711/732를 공용 코어 좌표에 대응시키는 구간별 변환을 사용한다. y도 메인복도 폭과 코어 깊이를 기준으로 구간별 변환한다. 증축부 길이·폭은 도면 기반 임시 좌표이며 cm/m 정확도로 해석하면 안 된다.
- 공통 계단 **입구**와 코어 주변만 수직 연결 근거다. 실제 계단 내부 3D 궤적·엘리베이터 문별 좌표·1층 정문/5층 야외 상세 통행 영역은 추가 작업이다. 미표시 구간에서 층 갱신이 보수적으로 보류될 수 있다.

검토 화면: `http://127.0.0.1:4175/navigation-review.html?floor=2`. 기존 2D 지도 상단에도 링크가 있다. 두 점을 찍거나 준비된 경로를 골라 통과 제한·미확인을 확인한다. 이것은 지도 검토 도구이지 웹 실시간 센서 측위가 아니다.

## 층 변화

안정된 초기 기압(최소 5개·1초, 변동폭 0.08hPa 미만)을 중앙값 기준으로 쓴다. 0.44hPa/층의 상대 변화, 최근 2.5초 창, 후보 지속 최소 3초와 착지 안정성을 확인한다. 콜백이 빨라지는 것만으로 층을 확정하지 않는다. IT홀은 `within_floor_elevation`으로 유지한다. 코어/사이드계단 근거가 약하면 `unconfirmed_vertical_location`이며 강제 가까운 계단 스냅은 없다.

위 수치는 초기 실험 파라미터다. 걸음 존재 여부는 계단/엘리베이터 **후보 이름**을 나눌 뿐 이동수단이 검증됐다는 뜻이 아니다. HVAC·날씨 변화와 느린 이동, 계단 내부 위치 손실에 대한 검증이 필요하다. 초기층 복수 후보의 공동 수직 추적도 후속 과제다.

## 실행과 재현

`app/expo-sensor-collector`에서:

```powershell
node scripts/test-floor-tracking.js
node scripts/test-position-tracking.js
node scripts/test-initial-positioning.js
node scripts/test-fusion.js
node scripts/replay-fusion.js
node node_modules/expo/bin/cli export --platform ios --output-dir .expo/fusion-export
```

실제 iPhone: 기존 Expo 서버/QR로 프로젝트를 열고 Reload → `실내측위 시험` → 기존 방식으로 후보 확인/기준점 지정 → 시작. 아래 `새 구역·2D 추적 엔진 · 비교 시험` 카드에서 구역과 좌표를 함께 확인한다. 기존 종료·공유를 누르면 기준선과 `derived_fusion`이 한 JSONL에 기록된다. 코드 번들 성공과 iPhone에서 재로드·보행 확인은 별개이며 이번 작업에서 실제 휴대폰 조작은 하지 않았다.

브라우저 테스트는 설치된 Playwright/Edge를 사용하여 `indoor/tools/test_navigation_browser.cjs`를 실행한다. 분석 산출물: `indoor/data/analysis/fusion-v1/replay.json`, `browser.json`, 2·3층 스크린샷. 원시 SHA-256 불일치 시 재생은 중단한다.

## 다음 적용 조건

1. 화면에서 누락 연결/잘못 표시한 벽을 확인하고 2·3층 통행 도면을 보완한다.
2. 코어/양쪽 계단 입구 전용 구역 반복 자료와 Android AP 스캔을 확보한다. 양쪽 복도 라벨이 분리되어 새 수집부터 구분할 수 있다.
3. 보폭·방위 편향·구역 융합을 분리 평가한다. 고정 끝점 스냅을 정확도 개선으로 계산하지 않는다.
4. 날짜·기기 분리 테스트와 앵커 복구를 검증한 후 Android 네이티브 추적에 통합한다. 지도·수집 기능은 계속 보존한다.
