# iPhone 실내측위 센서 수집기

## 설치형 iPhone BLE 환경 조사

2026-09-14부터 `BLE 환경 조사` 탭은 Expo Go가 아닌 **설치형 iPhone 개발 앱**에서 실행한다. 주변 BLE 광고의 RSSI를 같은 위치에서 수집해 건물 안에 고정된 신호가 있는지 먼저 확인하는 용도다. Wi-Fi AP 스캔을 대체하거나 현재 위치를 바로 확정하지 않는다.

- iOS 네이티브 `CoreBluetooth` 모듈은 `modules/ble-survey`에 있다. Expo Go에서는 모듈이 없으므로 버튼이 비활성으로 보이는 것이 정상이다.
- `BLE 환경 조사`에서 층·구역·메모를 고르고 같은 자세로 30초 이상 정지해 수집한다. 송신기별 RSSI는 최대 초당 1회 JSONL로 저장한다.
- JSONL에는 BLE 원시 식별자와 광고 이름을 쓰지 않는다. 세션 간 비교용 익명 ID, RSSI, 서비스 UUID, 송신세기 유무·연결 가능 여부만 저장한다. 화면에만 광고 이름을 잠시 표시한다.
- 휴대폰·이어폰처럼 이동하는 신호는 나중에 지문 앵커에서 제외한다. 같은 지점과 다른 지점에서 반복해 신호가 안정적인지 분석한 뒤 사용 여부를 정한다.

### iPhone 설치 빌드

Windows에서도 EAS 클라우드 빌드로 개발용 iPhone 앱을 만들 수 있다. 이 저장소에는 `eas.json`, iOS bundle ID `com.jhh4835.indoorsurvey`, Bluetooth 사용 설명과 `expo-dev-client` 설정이 준비되어 있다. 실제 빌드는 Apple Developer 계정·등록 기기·소스 업로드가 필요하므로 아직 실행하지 않았다.

```powershell
npx eas-cli@latest build --platform ios --profile development
```

빌드 설치 후에는 `npx expo start --dev-client --lan`으로 개발 서버를 열고, 설치한 앱에서 접속한다. Expo Go는 기존 센서 수집에만 계속 사용할 수 있다.

2026-09-14: 갤럭시 업데이트 제외. Expo 기본 복도는 계단 입구까지로 수정해 정·역방향 비교 시작좌표를 유지하고 계단 내부 수집은 별도 유지. 45개 경로/공용 엔진 회귀 통과. [측정 안내](../../docs/MEASUREMENT_20260914.md).

2026-09-09 구현·검증: [완료 항목과 남은 검증](../../docs/IMPLEMENTATION_20260909.md). 기둥 왼쪽 진입, 증축부 각도 완화, 8개 통로 연결, 패턴 진단 추가. Android 업데이트 제외. 패턴28회 비교·적용0회, 기존4회 평균 약3.87 지도 단위로 정확도 향상 주장은 보류.

2026-09-07 화면 배치: 경로 라벨 비교는 `보정 수집 경로` 바로 아래에 `현재 예상 위치`를 배치한다. `현재 지점 기록`은 측정 시작·종료와 같은 하단 조작 영역에 둔다. 측정 중에는 기존 PDR·패턴 OFF·패턴 ON이 각각 판단한 층을 한 줄로 먼저 표시하고, 이어서 각 강의실·구역 예측을 보여준다.

2026-09-07 복도 이탈 보완: 새 엔진 OFF/ON 모두 확인된 메인 복도 근처에서 작은 방위 편차를 완화한다. 직진 방위 차이는 복도 후보가 우세할 때만 완만하게 추정하고, 횡방향만 중심으로 완화한다. 열린 영역/증축부 내부와 큰 방향 전환에는 적용하지 않는다. `센서 기준점`은 기존 정지 구역 기준점의 새 화면 명칭이며 실제 측정은 같은 자리에서 정지해 수행한다. 보폭·거리 정확도는 별도 검증 대상이다.

2026-09-07 조작 개선: 경로 랩 버튼과 자유 이동 라벨 저장 버튼 바로 위에 세 방식의 현재 예측을 표시한다. 경로 선택에서 `정방향/역방향`을 고른 뒤 표시된 시작점에서 측정을 시작한다. 역방향은 마지막 랩을 시작점으로, 중간 랩은 역순으로, 원래 시작점은 마지막 랩으로 사용한다. 세션에 `route_direction`과 `source_route_id`를 저장하며 기존 원본 경로는 변경하지 않는다. 측정 중 방향 변경은 불가하다. 지도 시작 좌표가 없는 특수 경로의 센서/랩 수집은 가능하지만 예측 지원을 보장하지 않는다.

2026-09-07 접속 복구: LAN Expo 서버의 iOS manifest/개발 번들 HTTP200 확인. Expo Go 실행에는 export 빌드 외에 실행 중인 개발 서버가 필요하다. 같은 Wi-Fi로 접속하며 학교망 기기 간 차단 여부와 실제 iPhone 로드는 별도 확인한다. 외부 터널은 이번 복구에서 사용하지 않았다.

2026-09-07: `실내측위 시험` 시작 시 기존 1차원 PDR과 **새 구역·2D 추적 엔진의 자기장 8걸음 패턴 OFF/ON**이 함께 동작한다. 새 추정은 schema 6 `derived_fusion`에 `comparison_variant`로 분리 저장하고, 종료에는 OFF/ON 최종값을 모두 남긴다. ON은 후보가 충분히 분리될 때만 반영한다. 실제 안내용 확정 위치가 아니다. 세부 검증/제한: `indoor/docs/FUSION_V2.md`.

Expo Go에서는 기존 프로젝트를 Reload해 기존 센서 수집을 계속할 수 있다. BLE 환경 조사는 설치형 개발 앱에서만 쓸 수 있으며, iPhone 실제 Bluetooth 권한·스캔과 현장 신호 안정성은 별도 확인이 필요하다.

2층 책상·증축부는 기둥/TDM 옆 진입구 시작 V2로 바꿨다. 구역 수집은 오른쪽/왼쪽 강의실 라인을 구분해 `zone_id`로 기록한다. 과거 일반 강의실 라벨에 임의로 좌우를 붙이지 않는다.

Expo Go에서 실행하는 연구 데이터 전용 수집기다. 최종 iOS 앱을 만드는 목적이 아니라 iPhone 13 Pro의 가속도·자이로·자기장·기압·Device Motion·걸음 데이터를 JSONL로 수집해 Android 자료와 비교한다.

화면 상단에서 기능을 분리한다.

- `자유 이동 비교`: 예상 시작 위치를 확인하거나 수정한 뒤 자유롭게 이동한다. 실제 지점을 선택해 랩을 저장해도 추적은 계속된다.
- `경로 라벨 비교`: 알려진 경로를 선택하고 안내된 중간 지점에서 랩을 기록한다. 시작 좌표가 연결된 경로는 화면 위 `현재 예상 위치`에서 기존 PDR·새 엔진 패턴 OFF/ON의 예상 강의실·구역을 확인한다. 미연결 경로는 예측 불가 안내와 센서·랩 기록을 제공한다.
- `경로 라벨 비교`의 다중 센서 구역 기준점: 강의실 라인·양쪽 계단 앞/내부·코어 교차점에서 정지 센서를 수집한다. iPhone은 일반 주변 AP BSSID·RSSI 스캔을 제공하지 않으므로 Android AP 로그와 분석 단계에서 비교한다.

## 실행

의존성이 설치된 현재 개발 PC에서는 다음 명령으로 실행한다.

```powershell
node node_modules\expo\bin\cli start --lan --go
```

Android Studio 터미널에서 `node`를 찾지 못하는 현재 개발 PC에서는 Codex 번들 Node의 전체 경로를 사용한다.

```powershell
& "C:\Users\20222967\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe" "node_modules\expo\bin\cli" start --lan --go
```

다른 PC로 소스만 옮겼다면 Node.js와 npm 또는 pnpm으로 의존성을 먼저 설치해야 한다.

터미널 QR을 iPhone 카메라로 스캔해 Expo Go에서 연다. 같은 Wi-Fi에서 연결되지 않으면 다음을 사용한다.

```powershell
pnpm start:tunnel
```

## 경로 선택

- 1~10층을 먼저 선택한 뒤 해당 층의 경로를 선택한다.
- 기본 좌·우 메인복도 랩은 공용 `indoor/web/data/maps/floor-XX.json`에서 생성한다.
- 1층 정문·야외복도, 2층 개방·학습·증축부, 3층 증축부·IT홀, 5층 야외공간 경로도 Android 수집기와 같은 정의로 제공한다.

## 첫 비교 실험

1. `4층 코어 → 오른쪽 계단`을 선택한다.
2. 코어복도 출구 중앙점에서 4204 방향으로 휴대폰을 든다.
3. 측정을 시작하고 각 강의실 앞에서 현재 지점 기록 버튼을 한 번 누른다.
4. 오른쪽 계단 입구 도착 랩을 기록한 뒤 측정을 종료한다.
5. JSONL 저장·공유를 눌러 파일 앱 또는 메신저로 내보낸다.
6. 같은 방향·자세로 3회 반복한다.

## 다중 센서 구역 기준점 수집

1. `보정 데이터 수집 → 다중 센서 구역 기준점`을 선택한다.
2. 층과 `강의실 라인 / 왼쪽·오른쪽 계단 앞 / 왼쪽·오른쪽 계단 내부 / 코어 교차점`을 선택한다.
3. 세부 위치는 필요할 때만 `4204 앞`처럼 메모한다. 비워도 `층 + 구역 라벨`로 측정할 수 있다.
4. 측정을 시작하고 같은 위치·휴대폰 방향으로 10~20초 정지한 뒤 종료하고 JSONL을 공유한다.
5. 같은 조건으로 3회 반복한다. Android에서는 같은 층·라벨로 다중 센서+AP 기준점을 별도 수집한다.

`experiment_mode=multisensor_zone_anchor`, `sensor_scope`와 `radio_observation.nearby_wifi_scan_supported=false`는 사용할 수 있는 센서를 모두 기록하되, 일반 주변 AP 스캔은 iPhone API에서 제공되지 않는다는 뜻이다. 이는 AP 0개 관측과 구분한다.

## 자유 이동 실내측위 시험

### 내부 자동 추정

1. `내부 자동 추정`에서 `현재 위치 5초 분석`을 누르고 현재 자리에서 휴대폰을 평소처럼 든 채 멈춘다.
2. 앱이 자기장 크기와 절대 나침반 방위를 기존 참조 지문과 비교해 예상 층·강의실과 상위 후보 3개를 표시한다.
3. 맞으면 `맞아요 · 여기서 추적 시작`을 누른다. 틀리면 `아니에요 · 현재 위치 선택`에서 실제 층과 강의실·시설을 선택한다.
4. 기준 기압 5개가 모일 때까지 잠시 멈춘 뒤 원하는 강의실이나 다른 층으로 이동한다.
5. 화면에서 확정 층, 복도 좌표와 가까운 강의실 1·2순위를 실제 위치와 비교한다.
6. 시험 종료 후 JSONL을 공유한다. 자동 후보와 사용자 수정 여부도 시작 설정에 함께 저장된다.

현재 동일 기기 참조 지문은 iPhone 13 Pro의 4층 오른쪽 복도 3회뿐이다. 4층 iPhone 직접 지문만 같은 층에서 비교하면 정확한 노드 1순위 `36.1%`, 상위 3개 `52.8%`였다. 실제 앱처럼 Galaxy→iPhone 변환 지문으로 1~5층 후보를 모두 열면 층 정확도 `86.1%`, 정확한 노드 1순위 `25.0%`, 상위 3개 `38.9%`, 평균 복도 x 오차 `33.3` 지도 단위였다. 따라서 자동 후보는 사용자 확인 전까지 확정 위치가 아니다.

### 자유 이동 랩 기록

중복된 `기준점 지정 비교` 선택지는 제거했다. 통제 경로 실험은 `경로 라벨 비교`를 사용한다. 자유 이동 중 실제 층·지점을 고른 뒤 `랩 N 저장`을 누르면 번호·시각·누적 걸음·실제 라벨과 세 방식의 예측을 같은 JSONL에 기록한다. 저장 이력을 표시하고 추적은 계속하며, 측정 종료 시 총 랩 수를 남긴다. 랩마다 별도 파일을 만들지는 않는다. 평가 라벨로 예측 좌표를 강제 초기화하지 않는다.

층은 시작 층의 상대기압을 기준으로 최근 3샘플 중앙값, `0.44 hPa/층`, 동일 후보 3회 연속 확인을 거쳐 1~10층 범위에서 갱신한다. 층 전환이 확인되면 당시 PDR 위치에 가장 가까운 코어 또는 양쪽 계단 연결점으로 지도 좌표를 정합하고 새 층의 강의실 노드를 검색한다.

현재 수평 위치는 4층 오른쪽 iPhone 반복 로그의 가속도 피크와 임시 보폭을 사용한 메인복도 1차원 시험값이다. 진행 방향은 `expo-location`의 절대 나침반 방위로 복도 방향을 분류하고, 값이 없을 때만 Device Motion 상대 회전을 사용한다. 코어 안쪽·증축부·야외 공간과 정확한 방 문 앞 판정은 아직 보장하지 않는다.

이 시험은 시작 층과 시작 지점을 알고 시작하는 상대 추적이다. 날씨에 따라 달라지는 절대기압만으로 시작 층을 자동 판정하지 않는다.

## 데이터 원칙

- 기존 반복 파일 schema 4와 이전 자유 추적/구역 파일 schema 5를 보존한다. 이번 신규 파일은 `schema_version=6`이며 heading 샘플, 구역 ID와 실험 비교 결과를 추가한다. `collector=expo-go` 또는 `collector=ios-development-build`, `platform=ios`로 Android 원본과 구분한다.
- 기기 이름과 일련번호는 저장하지 않는다.
- iPhone 데이터는 `indoor/data/raw/ios/YYYY-MM-DD`에 별도로 보존한다.
- 가속도는 Expo의 g 값을 `9.80665`로 곱해 Android와 같은 `m/s²` 단위로 저장한다.
- 자기장은 `magnetic_field_ut`, 기압은 `pressure_hpa`, 걸음은 `step_counter` 센서 이름을 사용한다.
- Device Motion 회전은 Android quaternion과 혼동하지 않도록 `device_motion_rotation_rads`로 따로 저장한다.
